# Typed editor events

Status: accepted implementation contract. The event layer is a small per-editor notification API, not a command bus or plugin dependency system. No runtime dependency or global editor channel is introduced.

`createPluginEvent<T>(name)` creates an opaque SSR-safe token. Plugins export shared tokens from their contracts and use `editor.events.on(token, listener)` / `emit(token, payload)`. Equal display names do not merge independently created tokens. Core owns reserved string events `change: EditorChange`, `selectionchange: TextSelection | undefined`, `readonlychange: boolean`, `localechange: EditorLocale`, `inputcommit: EditorInputCommit`, and `destroy: void`. Public emit accepts only plugin tokens; reserved lifecycle events cannot be spoofed. Existing subscribe/onSelectionChange remain compatible signatures.

Delivery is synchronous FIFO: nested emit queues behind the current notification. Listener sets are snapshotted; removed listeners are skipped and new listeners wait for the next event. All current listeners are tried even if another throws; errors are reported in an AggregateError after the queue drains. Notification errors never roll back committed document/history state. Core payloads are independent snapshots per listener; plugin payload ownership remains with the emitting application (no arbitrary deep cloning).

Read-only events represent real state transitions. Selection events within a transaction wait for the final commit or rollback. Destroy marks the editor inactive, delivers the final destroy event, stops ordinary queued delivery and clears all subscribers even if teardown callbacks fail. Dispose functions remain safe and idempotent after destroy. Setup failure also tears down the event resources.

Acceptance: native/API/history notifications, aliases, typed custom payloads, same-name token isolation, per-editor isolation, add/remove/reentrant order, listener errors with committed history, destroy during delivery and throwing cleanup, SSR-safe factory, rejected reserved emission. No wildcard topics, transport, async subscribers, middleware, cancellable mutations or collaborative state is implied.

Custom editor.events.emit inside a document transaction is rejected and poisons the outer operation even if caught. Emit notifications only after a successful transaction; no extra buffering is introduced.

## Controlled input commit receipts

`EditorInputCommit` is a reserved core notification, not a command or cancellable transformation hook. Its readonly fields are `inputType: 'insertParagraph' | 'insertFromPaste'`, `sourceEvent: Event`, `selection: SelectionBookmark | undefined`, and `isCurrent(): boolean`. Register through `editor.events.on('inputcommit', ...)`; public emit cannot spoof it.

This bounded slice notifies only a changed, successfully validated core-controlled paragraph insertion or actual clipboard paste from a cancelable cause event. Noncancelable paragraph/paste input is excluded from receipt eligibility even where legacy editing behavior is preserved. Root/plain/wrapped list Enter paths are covered where core owns their mutation. `sourceEvent` retains exact identity of the causal beforeinput, direct plain-list keydown, or clipboard paste event, allowing a plugin-local WeakMap to correlate bounded preparation. The normalized list beforeinput itself is the cause when that path is used. The event object is context only: changing it cannot cancel the already committed mutation. Native-only input without a controlled path, Shift+Enter, blocked/canceled/no-op/rejected operations, composition, API insertHTML/setHTML/setJSON, ordinary plugin commands and history do not produce a receipt. This is not a universal input middleware API.

Capture the committed snapshot, structural post-input bookmark and pending caret-format state before notifying observers. Deliver the operation's existing change and selectionchange notifications before inputcommit; reentrant notifications retain the existing synchronous FIFO rules. Each listener receives independent bookmark objects/path arrays, while sourceEvent identity and the readonly predicate are shared. No clipboard payload or untrusted mutation callback is added.

`isCurrent()` returns false after disposal, read-only/composition activation, a different committed snapshot, a changed actual structural selection, or changed pending caret-format overrides. Observers that replace/edit/undo the document or move the selection therefore invalidate a follow-up prepared against the receipt. Callers must also revalidate their bounded candidate/context; this predicate is not an authorization token or support for arbitrary untracked direct DOM mutations. Moving selection away and back without editing can leave the same current state. The predicate does not move focus or selection and does not scan/diff the whole document.

Receipt delivery and observer failures occur outside rollback. A change/selection observer exception does not prevent attempting inputcommit, and all notification errors are reported after those attempts. Listener mutation is a separate validated transaction/history operation; a receipt cannot retroactively merge history. Destroy during delivery suppresses remaining ordinary events according to the existing lifecycle contract.

Acceptance: exact cause-event identity for controlled paragraph/list Enter and real paste; no receipts for API/cancellation/no-op/blocked/IME/Shift+Enter; change/selection/receipt order; independent listener bookmark arrays; observer errors with committed content/history and receipt delivery; isCurrent invalidation by nested edits, external replacement, structural selection and pending formats; stale receipts and cleanup. Optional autolink may consume this notification without adding a core import edge or timer/observer/diff pipeline.

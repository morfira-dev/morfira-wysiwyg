# Horizontal rule

Status: first optional explicit horizontal-rule command slice; actual validation results belong to verification-backlog.md.

## Document and editing contract

The command inserts an ordinary, attribute-free HTML HR already supported by schema v1. It does not add a document tag, semantic marker, schema contribution, custom element or persisted UI. HTML/JSON round trips do not require this plugin to retain the separator. The existing Markdown shortcut remains independently selectable.

Supported native selections are a caret or a range whose endpoints belong to the same ordinary P/H1–H6 directly under the editor surface. The block may contain ordinary inline formatting, links, inline code and BR. A block containing any image, owning semantic marker (`data-mw-node`) or structural descendant is unsupported, including when that descendant lies outside the selection. The image restriction avoids cloning retained resource-bearing nodes merely to split text. Root-level boundary selections, cross-block ranges and selections inside lists, quotes, tables, figures/captions or PRE are disabled. Unsupported commands do not move the selection, change content, clear redo or create history.

Insertion replaces the selected content with three sibling nodes: the original-tag prefix block, a bare HR, and an original-tag suffix block. Keep both edge blocks, their existing attributes and retained inline content; an empty edge receives a BR placeholder. A heading stays a heading on both sides, including an empty suffix. Applications can use existing paragraph formatting afterward; this first slice does not silently convert the suffix to P. Unrelated siblings retain their identity and order. The post-command native caret is at the start of the actual suffix block, after the HR in DOM order; text offsets alone cannot distinguish empty edges around a zero-text separator. An initially collapsed caret retains its existing effective typing affinity. An initially expanded selection invalidates stale collapsed overrides through the ordinary outer transaction contract, even when the resulting caret shares the earlier text offset and selectionchange has not yet fired.

This bounded command performs its own structural DOM split through a validated typed command transaction. It does not delegate to `insertHTML('<hr>')` or establish general-purpose raw HTML insertion support for separators across arbitrary containers. Any general insertion corrections require their own contract and regressions.

## API and lifecycle

The selective public subpath is `@morfira-dev/wysiwyg/plugins/horizontal-rule`. It exports `horizontalRule(): EditorPlugin`, `horizontalRuleCommands(editor): HorizontalRuleCommands`, and the named `HorizontalRuleCommands` / `HorizontalRuleState` types. The plugin identity is `horizontal-rule`; `insert(): void` executes the registered command and `getState(range?: Range): HorizontalRuleState` returns a fresh `{ disabled: boolean }` value. An optional saved native Range projects read-only command state for controls that hold editor selection while focused outside the surface. Both endpoints must still satisfy the same editor-root and source-block eligibility checks. Reading state does not change the live Selection, document, history or notifications, and it retains registry read-only/composition guards. It does not authorize execution: insert always validates the current native selection, so a control must restore its saved selection before activation. Missing installation throws when resolving commands. Retained handles throw after plugin/editor disposal.

Mutation uses the per-editor typed command registry, including its read-only and active-composition guards. A successful insertion is one transaction, one user-origin change and one undo step; Undo restores the original content and selection direction, while Redo restores the separator and editable suffix caret. Disabled insertion is a no-op. External replacements continue to follow the core API contract. Setup owns only its registration and provided API; disposal releases both, with no listeners, observers or global editor state.

The plugin has zero runtime dependencies and no mandatory CSS. Imports are SSR-safe. Optional presets and ready UI compose it outside core; their defaults, feature switch and localized button follow editor-presets.md and editor-ui.md. Native HR has implicit separator semantics; the command adds no focusable decoration or accessibility role. This slice does not claim full separator keyboard/navigation accessibility or arbitrary structural selection support.

## Acceptance and size

Chromium, Firefox and WebKit cover a rich backward selection split with actual sibling HR/caret/history, representative collapsed paragraph/heading edges including an empty heading, retained attributes and unaffected siblings, unsupported structural/semantic/root/cross-block ranges without mutation, read-only/composition guards, per-instance ownership and stale handles. Existing codec HR round trips remain the persisted contract. Demo and bilingual docs describe both supported behavior and limits. Tests cover distinct failure risks rather than multiplying every source tag, edge and guard combination.

Selective imports, declarations and actual package consumers must resolve the new entry without pulling it into core-only imports. Measure the complete plugin and chosen preset closures as minified JS, gzip and Brotli separately; report CSS independently, count shared chunks once and retain the existing preset budgets. No framework runtime, source map or declaration bytes are part of the JS measurement.

The explicit command-only plugin has a 5000-byte minified JS entry-closure guard in `scripts/size.ts`. This small feature-specific bound reflects the limited root-block split scope and absence of UI/node views or processing resources. Existing core, table, adapter and selected preset budgets remain unchanged; CSS stays in the shared core content stylesheet for the existing HR schema tag.

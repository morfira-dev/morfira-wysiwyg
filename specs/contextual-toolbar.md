# Contextual text-formatting toolbar — U3b

Status: accepted first implementation contract. Actual results belong to verification-backlog.md.

## Composition and public API

Provide independent `@morfira-dev/wysiwyg/ui/contextual` and `/ui/contextual.css` entries. Export `createContextualToolbar(host, editor, options?): ContextualToolbarController`, explicit `ContextualToolbarOptions`, `ContextualToolbarController`, `ContextualToolbarMessageKey` types and `contextualToolbarMessages` RU/EN catalog. The controller has readonly element, refresh():void and idempotent destroy():void. Options expose groups, density, label and onError from the existing EditorUI contracts, plus gap?:number (finite 0–32 CSS px, default 8). Default groups are bold/italic/underline/strike/code and clear. Explicit custom groups reuse EditorUIItem validation/commands, not a second formatting engine. The wrapper composes createEditorUI; it owns only eligibility, visibility, geometry, keyboard entry/exit and cleanup. No core imports of this optional module, runtime dependency, required framework or implicit preset/standard-UI installation.

The empty connected application-owned host must be outside the editor surface and in its owner document. Mount one owned wrapper there; do not move application DOM or create a global overlay service. Fixed positioning uses a viewport overlay layer: transformed/filtered/perspective/paint-contained or clipping host ancestors are unsupported, and applications must choose an appropriate overlay host. This first slice does not implement portals, arbitrary transformed-coordinate mapping, image/table popovers, collapsed-caret link menus or custom atom/node selection.

## State projection shared with the existing shell

Add nonbreaking `editor.getFormats(range?: Range)` for side-effect-free current-document format projection. No argument preserves existing native-selection/typing-override behavior. An explicit contained Range reads stored formats/list state from that range without moving focus/native selection or applying pending typing overrides. Foreign/detached ranges yield an empty snapshot; malformed runtime values throw. Projection confers no execution authority; commands still validate the actual current selection. UI-owned ranges are invalidated on API replacement.

EditorUIAction label/enabled/pressed readers gain an optional second Range parameter (a clone of the UI-owned valid range); existing one-argument callbacks remain compatible. Shell refresh preserves native getFormats() while a valid native editor selection exists, including pending caret overrides. If native selection is unavailable, it projects built-in state and clear eligibility from its remembered current range, including when WebKit drops Selection on toolbar focus. Mutating custom activation restores valid selection before the enabled recheck. Custom readers remain trusted synchronous side-effect-free callbacks; native-selection-only APIs are not automatically projected, and callers must use the supplied range/appropriate explicit state reader. Do not proxy Editor or temporarily mutate native Selection to read state.

## Visibility and selection

Show automatically for one noncollapsed native Range containing nonempty text wholly within the focused editor surface, with both endpoints and their ancestors ordinary HTML rather than owning semantic nodes/foreign namespaces. The operation changes no document/selection merely by opening, laying out or closing. Geometry must have a finite nonzero visible rectangle. Image-only/BR-only selections, collapsed/outside/root-invalid or nonvisible selections do not show. Core formatting retains its existing selection/atomic barriers; showing a toolbar does not broaden structural replacement/formatting contracts. Merged-cell selections are not reinterpreted as a new cell selection model.

Keep the toolbar and saved exact range/direction when focus moves into its own controls, even if the native Selection disappears. Pointer control activation reuses shell capture/restore. Editing goes through existing validated synchronous operations/history; one action creates its normal single Undo revision, preserving surrounding text and backward selection where the action preserves it. External value replacement synchronously invalidates and hides controls; retained detached nodes/clicks must not edit the replacement. Read-only and composition hide/suppress mutating context UI while external replacement remains possible.

Escape, outside pointer interaction, focus leaving editor/toolbar, API replacement, read-only and composition dismiss the panel. Escape returns to the editor and restores the saved range once; outside interaction never steals focus or restores an old selection. Closing for dismissal suppresses immediate reopening by queued selectionchange/RAF/refresh of the same range; a fresh eligible range or explicit Alt+F10 can reopen. Restoring editability/compositionend/API replacement alone must not resurrect a stale range. A subsequent genuine editor selection action may capture a new eligible range, including reselecting the same text. A successful formatting action may remain visible on its current valid selection.

Alt+F10 on this editor surface with an eligible text range opens/focuses the first enabled contextual control. It does not intercept shortcuts from other fields/editors or show for a caret. Reuse shell roving arrows/Home/End and native controls; Escape handling closes before the shell's return-focus handler can reopen it. Automatic showing never steals focus. Hidden controls have no visible/Tab-accessible subtree. Localized toolbar label/help/status use plain text; custom labels/errors never enter innerHTML. Existing CSS focus/reduced-motion/forced-colors behavior remains, without claiming complete screen-reader/mobile certification.

## Geometry and lifecycle

Use fixed viewport coordinates from the current remembered range, place above when space permits, otherwise below, clamp to the visible viewport with a small margin and wrap/scroll oversized groups rather than overflow the page. Intersect the anchor with the editor and ordinary clipping scroll ancestors; hide when the text anchor leaves visible bounds. Account for window/ancestor scrolling and viewport resize, including VisualViewport when available. Coalesce updates in one owned requestAnimationFrame; no continuous polling. Scroll/resize/geometry observers are active only during an eligible selection session. Geometry-only hiding outside the clipped viewport may retain those observers so scrolling back can reveal the same valid selection; dismissal/ineligibility removes them. Selection/lifecycle discovery subscriptions may remain for the controller lifetime. Guard every queued callback and cancel it on dismissal/ineligibility/destroy; release listeners, ResizeObserver and core subscriptions, including setup rollback and editor destruction. No resize/scroll loop, document normalization or document-wide node traversal.

Refresh after destruction throws; destroy is idempotent and does not destroy the editor. Reject malformed options/nonempty/foreign/inside-surface hosts before changing their content. Setup failure restores an empty accepted host and releases the inner shell. State and dismissal belong to each instance; no cross-editor range/shortcut leakage.

## Acceptance, examples and weight

Use representative Chromium/Firefox/WebKit definitions, not a Cartesian expansion: rich/backward/mixed selection and one Undo; explicit getFormats projection without focus/Selection changes including lost native Selection; keyboard Alt+F10/Escape and suppression; pointer/outside/API/read-only/composition races; viewport edges/narrow host/scroll clipping/queued geometry; two instances, setup rollback/disposal/stale controls and SSR imports. Keep public type assertions adjacent. Docs add two RU/EN public-control scenarios for homepage/playground, localized labels, dark/narrow layout, actual formatting/history and host integration without repeating the core matrix.

Explicit CSS requirements are core style + existing ui/editor.css + new ui/contextual.css. Use scoped mw-* classes and --mw-* theme variables, no remotely loaded assets/icons/fonts or executable labels. Add only scoped placement/shadow/viewport rules; content CSS and persisted schema remain unchanged. Local preview stays available; the site is not published.

Package/facade/declaration/selective-import and installed-tarball checks include the new JS/CSS entries. Consumers mount, show, activate and dispose one explicit contextual controller without replacing default ready UI. Measure raw/gzip/Brotli/CSS independently, shared shell chunks once. Enforce 16000 gzip JS bytes for the contextual entry closure (existing shell plus placement/lifecycle), 2000 raw bytes for its extra CSS, and unchanged existing profile guards. Measure deduplicated standard-contextual-ready and standard-fonts-list-properties-text-direction-contextual-ready graphs with the additional stylesheet once, under standard 80000 gzip JS / 20000 raw CSS. Explain any real product reason before revising a guard. Run full check, docs build/tests and real installed consumers; final claims require actual runs.

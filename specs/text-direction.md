# Optional text direction

Status: accepted first implementation contract; actual verification belongs to verification-backlog.md.

## Scope and persistence

Provide the independent `@morfira-dev/wysiwyg/plugins/text-direction` entry: `textDirection(): EditorPlugin`, `textDirectionCommands(editor): TextDirectionCommands`, and explicit public `TextDirection`, `TextDirectionCommands`, `TextDirectionState` types. This is opt-in, outside preset defaults and ready-toolbar built-ins. No runtime dependency, stylesheet, listener, observer, automatic language detector or custom bidi engine.

Persist optional native `dir="ltr"` or `dir="rtl"` on p, h1–h6, pre, blockquote, ul, ol, li, td and th. The tag set refers to canonical schema tags after existing aliases: ordinary DIV→P import may retain dir; JSON still requires a canonical tag. HTML import trims/lowercases these two values and filters invalid values/other canonical tags. This tightens the previously unknown/filtered dir JSON boundary. Explicit JSON accepts only canonical lowercase strings on these tags; reject a recognized dir key with wrong tag, type or value before live DOM, selection/history or notifications change. The shared codec retains accepted values through initial/external values, HTML/JSON export/rendering, paste and history without plugin installation. Paste retains incoming dir only where the existing insertion profile retains its wrapper: single-paragraph inline flattening and first-block content merged into a destination keep destination direction and can discard incoming wrapper dir. Do not add inline bidi wrappers or silently change those paste profiles. Keep schema v1 with additive compatibility: older readers may discard dir, changing display. Do not add dir=auto, inline direction wrappers, CSS direction/unicode-bidi/writing-mode, bdi/bdo tags or automatic conversion of text/Unicode control characters. Native Unicode bidi remains browser-owned; this is not a spoofing or visual-order security guarantee.

## Commands and selection

`setDirection(value: TextDirection | false): void`, with `TextDirection = 'ltr' | 'rtl'`, sets/removes explicit dir on each target. Public payload validation precedes eligibility; invalid runtime values throw even without a supported selection or in read-only. Registry handlers retain validation. Valid unsupported targets and already-equal values return before entering a transaction, preserving selection, focus, redo and pending typing formats. Changing several targets produces one history/change revision, and commands compose through editor.transact. Read-only/composition use existing registry guards; external replacement remains allowed.

Resolve the closest ordinary HTML p/h1–h6/pre/blockquote/li/td/th for each native Range endpoint. An endpoint on a supported block targets that actual block. Support a caret, backward/same-block ranges, empty blocks and a consecutive sequence of sibling target blocks with one parent; both endpoint blocks are included even at a zero text offset. Only ASCII formatting whitespace may occur between sibling targets; an intervening non-target element or non-whitespace text is an atomic barrier. No root-wide tree walk or structural normalization. Root/outside endpoints, different parents/levels, foreign namespaces and owning semantic ancestors (including the target) disable the operation. Resolving from an endpoint may cross ordinary inline wrappers only: endpoints on/in unsupported structural wrappers such as ul/ol/table/tr/figure/caption must not fall through to an outer LI/TD/quote target. Both endpoints and all targets must share the same closest td/th, or all be outside cells; a selection across cells is refused, including merged-cell layouts.

Targets are containers: their child subtrees remain opaque and retain their actual nodes, content, task/schema metadata, attributes, styles and order. Direction inheritance can affect descendants without explicit overrides; do not flatten nested branches or recursively assign dir to them. An ordinary paragraph within an item/quote/cell targets that paragraph; bare item/quote/cell text targets its enclosing container. Cross-item selections through inner paragraphs with different parents are unsupported; ordinary sibling LI targets are supported. Whole-container direction differs from alignment and never changes text-align. Native range/direction remains exact after attribute mutation; Undo/Redo restore snapshots/selection and supported subsequent typing. Clone-based Enter/splits retain dir; the ordinary heading-end Enter path also copies validated explicit dir to its newly created paragraph. Existing whole-block heading/quote/pre retagging, paragraph-to-item/item-to-paragraph conversion, UL↔OL conversion and Markdown block transformations must copy only validated dir when both source/target support it, alongside their existing attribute policy. When unwrapping a directed LI with existing owned P/H bodies through list formatting or the supported first-body Backspace root exit, preserve its inherited direction by assigning the LI direction only to immediate preserved bodies without an explicit dir; never overwrite a body override or recursively assign nested branches. When the existing empty-single-body Enter exit deliberately flattens that body to a new paragraph, its canonical explicit dir overrides the LI direction on the exit paragraph; keep the existing output shape. Do not clone arbitrary attributes or metadata. List coalescing/indent reuse must additionally compare explicit dir: independently directed containers cannot merge and discard a direction boundary. This is not a promise of direction propagation for arbitrary structural deletion, joins or nested wrapper removal; native/document join rules continue to apply.

`getState(): TextDirectionState` returns fresh `{ disabled: boolean, direction: TextDirection | false, mixed: boolean }`. Direction reports stored attributes only, not inferred script or computed/inherited CSS. Different explicit values (including absent vs explicit) yield mixed=true and direction=false; unsupported targets yield disabled=true, direction=false, mixed=false. Reset removes explicit dir and follows surrounding/application direction, rather than forcing LTR. State reads are side-effect-free. Missing installation and stale handles after disposal throw; cleanup unregisters commands/provided state per instance.

## Acceptance, documentation and size

Representative Chromium/Firefox/WebKit definitions cover rich backward multi-block/node identity/range/history and actual computed direction with unchanged alignment; bounded block/list/Markdown conversion preservation and list direction merge barriers; Arabic/Hebrew/Latin text retained without reordering; reset/mixed/inheritance; nested/empty/list/quote and merged-cell targeting/barriers; plugin-independent HTML/JSON/paste round trips, malformed dir and CSS/attribute injection; invalid/no-op redo/pending retention; read-only/IME/external replacement/instance isolation/disposal; SSR-safe imports. Use distinct risks, not a Cartesian matrix. Public type declarations reject wrong command values. Test both supported native editing after properties and the unchanged boundaries of other operations.

RU/EN guide/API/list/plugin/roadmap pages and homepage/playground expose explicit composition, native LTR/RTL/reset controls, stored/mixed state and a multilingual sample. External controls preserve the saved selection. Two localized docs scenarios test public controls, history, read-only and responsive rendering rather than repeat the core suite. Keep the local preview available; no site publication.

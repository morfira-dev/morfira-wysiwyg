# Images: optional commands and application-owned upload

Status: implemented locally. The original image slice historically passed 306 browser tests across Chromium/Firefox/WebKit (60 image scenarios), docs build and 17 site tests. Those historical results do not validate the later resize/handle/alignment additions; see [verification-backlog.md](verification-backlog.md) for current evidence and unexecuted scenarios. Original strict TypeScript, zero runtime dependencies. Public entry `@morfira-dev/wysiwyg/plugins/images`; `images(options)` plugin and `imageCommands(editor)` API. Schema v1 adds semantic figure/figcaption tags (additive; older readers discard wrappers/caption semantics). Core never imports images plugin. A root document ending in figure receives a trailing empty paragraph, as for tables. Core insertHTML treats figure as a block.

## Commands and persisted data

`ImageValue { src: string; alt?: string; width?: number; height?: number; caption?: string; alignment?: ImageAlignment | false }`; `insert(value)`, `select(image)`, `getSelected()`, `update(partialValue)`, `remove()`. HTML/JSON image dimensions are authoritative and mirror into validated inline pixel styles to resist host stylesheet resets; updating/removing dimensions keeps both representations synchronized. Width/height are positive integer HTML dimensions 1–1000; undefined leaves metadata, null removes dimensions in update. Caption is literal text up to 5000 characters; empty removes it; alt up to 20000. URLs use the shared image schema (http/https or relative, no data/blob/script). Invalid values reject atomically before mutation.

Insert creates a block figure containing img and optional figcaption. Replace a selection only within the same paragraph/heading or container; reject selections across blocks/cells/list items atomically. A selected single-image figure is replaced as a unit (including its old caption), never nested. Reject insertion in complex imported figures. Split a paragraph around the figure and place caret in the following paragraph, preserving surrounding marks. Figures remain inside list items/table cells; merged-cell geometry remains unchanged. Caption editing uses native input/history. Updating a caption on a legacy inline image promotes it to a figure. Updates without caption keep legacy inline images in place; existing unrelated validated image attributes survive. Caption removal preserves the figure/image. Remove deletes the owned figure or just the inline img; unrelated surrounding/cell/list content stays intact. Commands form one undo transaction each, respect read-only and restore selection on history navigation.

`select(image)` requires this editor's img and selects its DOM node. Clicking an image selects it. The demo captures selection/metadata synchronously on image click before a rapid form-focus change; form focus retains that bookmark; getSelected/update/remove derive the actual current image selection, including a caret in its caption. A selection spanning multiple images is not a single-image selection. The subsequent numeric/keyboard proportional-resize slice follows [image-resize.md](image-resize.md); independent pointer/keyboard handles follow [image-resize-handles.md](image-resize-handles.md), and image placement follows [image-alignment.md](image-alignment.md). Crop remains future work, while optional clipboard/drop input has its own [image-input.md](image-input.md) contract.

`resize(size: ImageResize): void` accepts exactly one width or height integer 1–1000. `ImageResize` is `{ width: number; height?: never } | { height: number; width?: never }`. Use the stored dimension pair first, otherwise already-loaded natural dimensions; round the other side to the nearest pixel, reject unknown/invalid/overflowing proportions atomically and never fetch an image for sizing. Apply both HTML dimensions/pixel styles in one transaction, preserving the actual IMG, rich caption and surrounding structure. Identical sizes add no history; read-only/composition are no-ops. Eligibility, focus-time target checks and rounding limits are specified in image-resize.md. No claim of a newly executed browser run or measured bundle follows from this contract update.

`ImageAlignment` and `align(alignment)` follow [image-alignment.md](image-alignment.md): physical left/center/right placement of the actual IMG with bounded block/margin styles, reset via false, independent caption text alignment and one-step history. Insert/update accept the optional alignment field; omission preserves existing placement. No-op align adds no history. Read-only/IME, ordinary ownership and post-focus target guards apply. Core persistence is additive under schema v1; older readers may discard these styles. Browser acceptance definitions are authored but not executed locally for this stage.

## Upload lifecycle

Options `upload(file, { signal }): Promise<ImageValue>`, optional maxFileSize (default 10 MiB). Validate file.size >0 within limit and MIME image/png, image/jpeg, image/gif, image/webp, image/avif before callback. SVG/executable file formats rejected. Application owns transport, credentials, storage and server validation; the client MIME gate is not server-side validation.

`upload(file): Promise<boolean>` captures the current valid selection and awaits the callback, then validates the result and inserts one image transaction at that bookmark. Selection-only movement does not relocate the insertion. Return true on insertion, false when cancelled; errors reject for caller UI. `cancelUpload()` aborts the signal; `isUploading()` reports state. Latest request wins. Any document change/external replacement, composition start, read-only transition or disposal cancels the request; disposed APIs throw except idempotent cancelUpload. A request made during composition returns false before starting transport or changing selection. External document replacement and read-only activation clear the upload composition guard without requiring a later compositionend; uploads can resume after a fresh valid selection and read-only deactivation. Composition start aborts an existing request immediately; it resolves false and never restores its saved range, including when the callback settles during or after composition. Late results/rejections after cancellation cannot mutate or cause unhandled rejections. No temporary nodes or object URLs are persisted. Per-instance state only; dispose all subscriptions/listeners.

`upload(file, { signal }?)` additionally accepts an optional caller-owned `AbortSignal`. Aborting it cancels only that request, never a newer request. An already-aborted signal returns false before replacing any current upload. Remove the caller abort listener when the request settles. This additive argument lets optional forms own and clean up their pending upload without cancelling application or sibling-form work. Existing one-argument callers and global cancelUpload retain their behavior.

The reusable optional image form follows `specs/ui-forms.md`, with raw string drafts for src/alt/dimensions/caption, localized status/errors and scoped upload cancellation. Its selected-image aspect-ratio checkbox and optional default-false `keepAspectRatio` constructor option follow image-resize.md: linked drafts apply in one update, unknown proportions disable the checkbox and stale targets cannot receive old geometry. The independently imported drag-resize UI follows image-resize-handles.md. Immediate left/center/right/reset controls in this form follow image-alignment.md; they preserve the existing ImageFormValues shape and do not submit other drafts. Storage and cropping remain outside these UI modules.

Routine lifecycle correction: ignore composition-start events received while
already read-only, so a late browser event cannot leave uploads locked after
read-only is disabled. This preserves the existing cancellation/resumption
contract and adds no new editing capability.

## Local bilingual demo

Both homepages/playgrounds expose image sample, src/alt/width/height/caption fields, insert/update/remove, file upload and cancellation, loading/error status. The local demonstration callback returns /logo.svg for an accepted raster file and explicitly says it does not upload/store the selected file; it is a callback/lifecycle example, not a file preview or production upload. User files never leave the tab. Demo callback uses AbortSignal with timer cleanup. Show existing image metadata when selection changes, keep drafts during form focus. CSS variables control image/caption spacing, color and font size; scope styles to .mw-content.

# Everyday editing: lists and formatting toolbar

Status: implemented local milestone. Document version 1 and public imports remain stable; core/plugins remain dependency-free. Optional ordered-list start support and older-reader numbering losses follow [document-attributes.md](document-attributes.md). Current validation, generated bundle evidence and remaining limits are recorded in [verification-backlog.md](verification-backlog.md). No automatic Git publication is part of this local feature request.

## List commands and input

- `format('list', 'bullet' | 'ordered' | false)` affects only selected editable blocks/items. Adjacent compatible lists coalesce; changing/removing a middle item splits its containing list and preserves unaffected siblings, nested lists, inline content, links and images. List items must remain under ul/ol; block formatting inside an item changes its inner block, never replaces li with a heading under ul.
- `format('indent', 1 | -1)` indents/outdents a contiguous sibling range of list items, preserving their subtrees. Indent moves under the preceding sibling; the first sibling cannot indent. Outdent lifts one level; trailing nested siblings move under the last lifted item to preserve order. Root outdent removes list formatting. Maximum depth is eight list levels. Invalid multi-container selections reject atomically; read-only blocks mutation.
- Enter splits an item at the caret, preserving inline markup and moving the following content/sublist into the new item. A selected range within one item's own content is replaced before splitting. Enter on an empty root item exits into a paragraph, preserving following items; on an empty nested item it outdents one level. Shift+Enter inserts a line break inside the item.
- Backspace at an item's start merges it into the previous sibling with the caret at the join and preserves nested content. At the first sibling it outdents/unwraps one level. The bounded forward-Delete contract below and the separate `list-selection.md` contract extend specific deletion/replacement shapes; other shapes keep their explicitly documented owner. Arbitrary cross-container replacement normalization and native IME/mobile certification are not claimed.
- Tab/Shift+Tab indent/outdent outside tables. Inside cells Tab remains table navigation; toolbar indentation still works. Composition and modifier shortcuts must not trigger structural input handlers.
- Every structural operation is one history revision with exact selection restoration on undo/redo. Empty-item caret positions must not be confused with identical text offsets in neighboring blocks.

## Keyboard protocol for owned list operations

For an already owned list Enter, Shift+Enter, Backspace or Delete key intent, a cancelable keydown suppresses the browser default and dispatches exactly one bubbling, cancelable `beforeinput` with the normalized intended inputType. Shift+Enter uses `insertLineBreak`; Backspace/Delete use their corresponding content-deletion types. This bounded bridge is required because a browser can omit beforeinput at an inert root boundary or label Shift+Enter as insertParagraph. It does not use browser detection, browser editing commands or an alternative DOM mutation path. The existing validated beforeinput pipeline remains the only manual editing owner, including plugin capture hooks, preflight, transactions, typing state and selection/history.

The normalized event is constructed and therefore has `isTrusted === false`; consumers must not assume trusted native events for these owned key intents. A prior capture-phase keydown cancellation or capture-phase beforeinput cancellation prevents the operation. Already canceled/noncancelable keydown, read-only, composition/IME key code 229 and Ctrl/Meta/Alt-modified keys do not dispatch the bridge. Enter remains visible to optional beforeinput typing rules before the core bubble handler. Unowned keys retain their earlier native/legacy paths. No timer, deferred mutation or additional instance state/listener is introduced; disposal leaves all existing keyboard/input listeners inert.

Acceptance includes real root-first Backspace and Shift+Enter in each engine, exactly one beforeinput/change/history revision, original DOM-point Undo/Redo, capture cancellation, plugin consumption, noncancelable/modified/composition/read-only key guards and disposed surfaces. Current run evidence remains in [verification-backlog.md](verification-backlog.md).

## Bounded forward Delete — implemented locally

The new path owns a collapsed `deleteContentForward` at the end of an item's own inline body (directly under li or inside one ordinary p/h1–h6 wrapper in a supported body sequence). At an interior body boundary it joins the next body; at the final body boundary it joins the next item before any trailing direct `ul`/`ol` branches. Text, supported marks/links/spans/code and br are supported. A single br in an otherwise text-empty body is an editable placeholder, not an extra line to join. This path receives only cancelable, not already-canceled beforeinput; composition/read-only and modifiers retain the core input guards. DOM mutation remains in beforeinput; owned keydown normalization follows the keyboard protocol above and leaves single-body Backspace/lift behavior unchanged.

When the current and next sibling `li` belong to the same ordinary list and both have supported inline bodies, retain the left item and its attributes, append the right item's own body, and put the exact DOM caret at that join. Preserve both items' trailing nested branches as whole subtrees, in left-then-right order after the joined body. Do not coalesce those branches, rewrite their attributes, scan/join unrelated lists, or normalize their descendant DOM. Empty inline wrappers and their semantic metadata remain; remove only own-body placeholder br. Ordered-list start persistence follows `document-attributes.md`; these boundary commands do not add li.value properties or new SDK tags.

At a recognized own-body end, a final item, semantic item/list marker, unsupported body or unsupported next sibling is an atomic barrier: consume Delete without content, selection or history change. Do not merge out of a list, lift to its parent item or move across cells. Deletion inside a body remains native. The new handler uses the existing transaction/history; one undo restores the original list, exact caret and branches, redo restores the join, and subsequent native typing remains at that position with existing native mark-boundary affinity.

Acceptance fixtures cover ordinary and nested lists, merged-cell isolation, rich and Unicode joins, real br positions, empty placeholders, preserved branch attributes/DOM identity, unrelated siblings, barriers, one-step history and canceled/read-only/composition input. Current verification results and remaining limits are recorded in [verification-backlog.md](verification-backlog.md).

## Paragraph and heading sequences inside an item — implemented locally

A supported item contains either direct inline content or a nonempty sequence of ordinary `p`/`h1`–`h6` bodies followed by optional trailing direct lists. Each wrapped body contains the same supported inline nodes as direct bodies. Wrapped and direct siblings can join: retain the left li and its actual final body wrapper, including attributes; move only the right first body's children into that body and move subsequent right bodies as actual siblings before the retained branches. Nested branches remain outside wrappers. Semantic body wrappers, mixed direct inline/block content, source images and other structural children remain atomic barriers for the bounded paths.

Cancelable Enter/Shift+Enter within a supported wrapped item is owned before native mutation. Both endpoints must stay in that item; li offsets between bodies map a range start to the following body's start and a range end to the preceding body's end without changing the original history bookmark. A same-item selection crossing body boundaries first uses the bounded list replacement cut with an empty payload, preserving preceding/following blocks and branches, then performs the split or line break at its resulting caret within the same transaction. A selection crossing items, reaching a trailing list, a semantic wrapper or an unsupported p/h body is consumed without mutation for Enter/Shift+Enter. Ordinary empty-item Enter keeps the existing exit/outdent policy only for a sole body without branches; an empty body in a multi-body item splits normally rather than exiting the list.

Enter replaces a same-body selection, splits only its inline body, and creates a sibling li with the same li attributes and body tag/attributes. A heading at its end therefore creates another heading inside the next item. The original wrapper stays intact. Move subsequent whole bodies and unselected trailing nested branches after the new split wrapper. Empty split bodies get placeholders inside their wrappers, never loose br under li. Shift+Enter inserts a real br at the preserved starting inline context, with a terminal editable placeholder where needed, inside that same body. Semantic inline children retain their metadata.

Collapsed forward Delete at an interior body's end joins only its next body into the actual left wrapper, retaining its tag/attributes and caret at the join. At the final body's end it joins the next item's first body and preserves later right bodies, then both sets of branches. Backspace at an interior body's start joins it into the preceding body by the same rule. Backspace at the first body's start in a multi-body item follows the bounded join/lift contract below; single-body and direct-inline items retain their existing Backspace/lift behavior. No branch is normalized or scanned as part of a body join.

At a collapsed li-level boundary between bodies, Delete resolves to the preceding body's end and Backspace to the following body's start. Enter/Shift+Enter keep the following-body start preference. Original item-level coordinates are retained in the transaction snapshot for undo.

These operations use the existing guarded transaction/history path: one change and one undo, restoring exact original selection and wrapper content. Owned keydown routes the wrapped path through one normalized cancelable beforeinput rather than invoking a legacy split or relying on browser-specific native event emission. Canceled, noncancelable, composition and read-only input cannot trigger a manual wrapped mutation. Acceptance evidence and remaining limits are recorded in [verification-backlog.md](verification-backlog.md).

## First-body Backspace in a multi-body item — implemented locally

A collapsed Backspace at the first body's start (including an empty body's sole placeholder or item offset zero) is owned before native mutation. Preflight requires an ordinary supported multi-body item and a source list containing only supported ordinary items and formatting whitespace. Semantic list/item/body roots, malformed sibling content and unsupported containers are atomic barriers. Supported inline semantic metadata and untouched semantic ancestors remain intact.

If a previous sibling exists, merge the current first body's inline children into the previous item's final body. Retain the actual previous item and body, append subsequent current bodies as actual siblings, then both sets of whole trailing branches in previous/current order. Promote a direct-inline previous body to an ordinary p when the surviving blocks require it, following the existing forward-Delete rule. The caret lands at the join; the current first wrapper and item are removed. No global list coalescing occurs.

For the first item of a list directly under the editor, blockquote or td/th, remove that item from list formatting. Move its actual paragraph/heading bodies and whole branches before the actual remaining list; remove the list only when no items remain. Body tags/attributes remain; removed li attributes are not transferred onto every body. Keep the caret's inline node/offset or normalized first-body edge. A semantic blockquote ancestor is unchanged rather than stripped.

For the first item of a nested list, lift the actual item immediately after its ordinary owner item. Move following actual sibling items into a shallow clone of the source list appended after the lifted item's existing branches, preserving source order. Then move the owner's later actual list branches after that clone, or directly after the item's existing branches if no source siblings remain. Earlier owner branches stay under the owner. This preserves depth-first content order even when the source list is not the owner's final branch: current bodies/own branches, remaining source siblings, later owner branches. Preserve each moved branch's actual nodes, ul/ol kind and attributes without coalescing adjacent lists. Remove an emptied source list and never create an empty clone just to hold formatting whitespace. Before mutation validate the owner and outer list, plus every moved later branch as an ordinary supported list with supported direct items and formatting-only gaps; semantic roots, unsupported bodies or malformed moved branches remain atomic barriers. Never lift a table-cell list outside its cell.

Each successful operation is one existing synchronous transaction/change with exact original HTML and DOM selection restored by undo and result/caret restored by redo. Barriers preserve document, selection, pending caret state and history. Acceptance definitions cover rich/Unicode and empty starts, inline previous promotion, actual block/branch identity, root and nested lift, following siblings, merged-cell isolation, semantic/malformed barriers, cancellation, noncancelable input, composition, read-only and controlled adapter feedback. Acceptance evidence and current generated sizes are recorded in [verification-backlog.md](verification-backlog.md).

## Formatting and toolbar

- `format('clear', true)` clears inline marks, links and spans on selected text while retaining unselected formatting, blocks, lists, images and alignment. It is a no-op without a text selection.
- `getFormats()` retains values at selection start, reports nearest list type and block alignment, and adds `mixed: string[]` for nonuniform selected formats plus `listDepth`, `canIndent`, `canOutdent`. A mixed boolean toggle applies the mark to the whole selection. Existing boolean/format keys are retained.
- `ToolbarAction` adds optional `enabled(editor): boolean`. Built-in undo/redo reflect history availability. Buttons reflect true/false/mixed states; actions preserve DOM selection bookmarks, including empty items and keyboard activation. External document replacement clears the saved selection and pending state.
- Optional fourth `createToolbar` argument `{ label?: string }` localizes the toolbar accessible label. The default toolbar includes ordered lists, indent/outdent and clear formatting. All controls retain visible focus; ArrowLeft/ArrowRight/Home/End move among enabled buttons with one tab stop; Escape returns to the editor. Detached controls are inert after disposal and subscriptions/listeners are cleaned up. Read-only disables edit controls.

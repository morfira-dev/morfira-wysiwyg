# Paste and HTML insertion over ordinary sibling leaves

Status: accepted bounded implementation contract. Schema v1 and the public API remain unchanged. Source eligibility follows `input-replacement.md`: endpoints inside distinct ordinary p/h1–h6 siblings under one root, blockquote or td/th, with no structural or semantic root crossed.

## Import and ownership

Clipboard HTML has precedence over plain text. A nonempty HTML string that sanitizes to no nodes is a no-op, without falling back to text or deleting the selection. Plain text is escaped as literal data; CRLF, LF and lone CR become br. This explicitly extends previous LF/CRLF handling to lone CR. Canceled paste is left untouched; read-only and composition block user insertion.

Parse, validate and render the complete incoming fragment detached from the live document before the outer transaction. Invalid outer `insertHTML` throws without changing DOM identity, selection or history. A clipboard validation error is ignored atomically, without an uncaught event error. A validation failure from nested `insertHTML` still poisons its enclosing transaction even when application code catches it. Do not catch editing, commit or observer errors as import failures. Empty sanitized imports do not enter a transaction.

If the current document selection is outside the editor, preflight resolves the last editor bookmark without changing focus or the current selection. Invalid imports leave that outside selection untouched. A valid nonempty import restores the remembered editor range before opening the transaction, so the operation and undo baseline use the same preflight boundaries and direction.

## Composition

- Inline HTML and a single ordinary p are inserted in the actual starting inline context. The p wrapper is removed; the retained left wrapper/attributes win. The right suffix joins that left wrapper. The caret is after the payload, before the suffix. An incoming anchor is inserted outside an existing starting anchor to avoid invalid nested links; prefix metadata remains and the incoming link keeps its own attributes.
- Several ordinary p/h blocks use their children for the first block in the retained left wrapper. Its original attributes win over the first incoming wrapper. Middle blocks retain their tags/attributes. The final incoming wrapper also retains its tag/attributes and receives the right suffix, with the caret between payload and suffix. Placeholder br in an empty first/last payload leaf is removed before joining its edge; a middle empty leaf keeps one editable br. A br in a single-p payload remains an actual line break. Semantic p/h wrappers are not unwrapped or retagged.
- Structural or mixed fragments use a small sibling splice: preserve the left prefix wrapper, insert the validated root blocks after it, and retain the original right wrapper with its suffix. A suffix containing an empty semantic inline still counts as content. If no suffix content remains, create an ordinary editable p after the payload. The caret starts in that right wrapper before its suffix. Supported structural roots are blockquote/pre/hr/ul/ol/table/figure and p/h wrappers. A single incoming heading uses this branch and retains its own wrapper; only a single ordinary p is unwrapped. Loose inline runs in a mixed fragment are wrapped in p; formatting-only whitespace between root blocks is discarded. Detached orphan table parts, li or figcaption roots are rejected rather than inserted into an invalid parent.
- A table anywhere in the incoming fragment is rejected for an eligible source range inside td/th, preserving the current table atomically. A fragment containing a nested table (`table table`) is also rejected at the root. Figures are allowed in cells. This is not a nested-table implementation or a replacement algorithm across different cells.

All three paths reuse the same source boundary cut as native selection replacement: preserve the left prefix and real starting Range, extract the right suffix, remove only covered leaves and normalize empty placeholders without losing semantic inline metadata. Do not rebuild unrelated editor content. Empty resulting leaves remain editable.

## History and evidence

Caret-only formatting overrides belong to a collapsed selection. When a valid API/clipboard insertion replaces a noncollapsed range, clear those overrides inside the transactional mutation after capturing the original snapshot. A new caret at the same numeric text offset must not resurrect an override from an earlier collapsed selection. Invalid or fully stripped imports do not clear that state; neither do no-op boundary barriers. This rule does not introduce a forced formatting state for following native input.

One insertion creates one isolated validated history operation and one change notification. Undo restores exact original HTML and forward/backward DOM selection; redo restores the inserted document and caret. Following native input occurs at that caret as a separate operation, with existing native link-end affinity. Controlled feedback must preserve that selection and history. Read-only, composition, rollback and disposal retain existing contracts.

The inserted payload and its immediate DOM caret have the defined composition above; later native characters retain browser boundary affinity rather than a new forced-mark state. In particular, after a trailing pasted br immediately before a marked suffix, a subsequent character may inherit the suffix's mark or remain outside it, depending on the browser. Its logical insertion position before the retained suffix, the suffix's existing formatting, and separate undo history remain required. This does not promise identical subsequent mark inheritance across engines.

Chromium/Firefox/WebKit acceptance covers API and ClipboardEvent routes, literal multiline text, inline/single/multiple blocks, mixed and structural roots, payload validation/HTML precedence, merged cells, quotes, semantic inline/ancestor metadata, actual next typing, range direction and isolated history. Synthetic clipboard events do not establish OS clipboard permissions, Office fidelity or real-device IME behavior. Cross-container source ranges, selected lists/tables/figures, word replacement and drag/drop remain outside this slice. No dependencies, CSS, public exports or timing claims are added.

# Isolated package consumer verification

Status: accepted tooling contract. This checks installable package artifacts, not source aliases or npm publication. It adds no runtime/editor dependency. Angular compilation/linking tools remain development-only.

The runner requires an existing successful library build. It packs the eight libraries (core, plugins, Vue, React, Svelte, Angular, Web Component and facade) into real tarballs and creates a temporary consumer outside the pnpm workspace. Its dependency and pnpm workspace override entries point to those tarballs. Framework/compiler/bundler versions (including tsx, the runner’s existing tool and an explicitly installed Vite optional peer) and their transitive dependency edges are pinned to the actual installed repository graph. Version-qualified parent>child pnpm overrides preserve multiple compatible package versions instead of globally forcing one version. The runner bounds candidate directories and resolved paths to each graph’s own node_modules before accepting a package; loader/global lookup fallbacks are ignored. Peer-only edges require a binding in the package’s own node_modules or immediate pnpm peer context, so unrelated inherited/hoisted optional peers are recorded as absent instead of being imported into the graph. The runner follows each physical package context, fails on missing required dependencies or ambiguous parent/version edges, and verifies that the isolated installed graph matches before compiling. Uninstalled optional peers are recorded. Uninstalled optional dependencies, including platform-specific packages such as macOS-only fsevents on Linux, are recorded and removed in the isolated consumer through version-qualified parent>child pnpm overrides with target `-`. This reproduces their actual absence for exact versions and semver ranges alike; it does not guess a version or resolve an unavailable optional package from the registry. Required edges still fail when missing, and installed optional edges retain their exact installed versions. The small `pnpm run test:consumers` tooling regression suite runs before package builds in `pnpm run check`; it must exercise an actual offline pnpm install with a missing optional range and verify the resulting graph and required-dependency rejection. Installation uses pnpm 11.0.7 with `--offline`. A frozen CI install can populate package content without populating registry metadata, so exact registry versions alone are not sufficient for a fresh offline consumer. Development-tool roots and version-qualified edges therefore install from `file:` references to their verified physical installed package directories; pnpm imports their package files into the isolated consumer. Missing optional edges retain `-` overrides. The eight Morfira libraries remain real tarballs, never source aliases or links. Every installed toolchain realpath must remain inside the consumer node_modules and its normalized version/edge graph must match the source graph. No registry metadata or network fallback is required; missing physical required packages still fail explicitly. Regression acceptance includes an empty pnpm store and metadata cache, a transitive required tool with a semver range and executable bin, an absent optional range, and proof that installed tools resolve inside the isolated consumer.

The default consumer owns normal Vue SFC, React StrictMode, Svelte 5, Angular 21 and Web Component examples. It imports supported facade/adapter/plugin/CSS exports without TypeScript paths or Vite aliases, type-checks TS/TSX, Vue and Svelte, then creates a production build. Installed package and entry realpaths must remain within the isolated consumer node_modules; artifact versions and archive hashes are recorded. The check must not publish, modify manifests or install packages in the repository.

The React example includes a StrictMode wrapper; a production build does not exercise development-only effect replay (covered separately by the project adapter suite). Browser acceptance uses the built consumer in Chromium, Firefox and WebKit: real typing survives controlled feedback; a structural slash action produces one final change and supports history/following input; external values do not emit user changes; reactive read-only blocks input but accepts an external value; unmount removes editor and optional menus and disposes its API. Browser failures and page errors fail the run. These are recorded smoke scenarios, not broad mobile/IME/accessibility certification.

Every adapter fixture also imports the public `ui/links`, `ui/images`, `ui/search` and `ui/forms.css` exports from installed facade artifacts. The three optional forms mount in separate application-owned hosts, with the image and search plugins explicitly enabled. Browser smoke acceptance applies a link, inserts an image from a local fixture asset, replaces a search match and undoes each mutation; read-only disables form mutations while allowing Find. Unmount removes all form controllers and their owned host. These checks exercise public controller types and package/CSS resolution as well as browser behavior, including the Angular 22 profile. Each successful browser scenario records `uiForms: true`; detailed form edge cases remain in the dedicated behavior suites.

The runner binds an ephemeral localhost port, closes pages/browsers/server and removes its owned temporary directory in finally. A JSON report under ignored artifacts records package/tool versions, archive hashes, resolved artifact locations, the root lockfile SHA256, exact toolchain edge overrides/absent optional packages and actual browser results. No unstable timing assertion or registry availability is part of acceptance.

## Angular compiler profiles

Before the default browser consumer is installed, a separate minimal temporary consumer declares only the facade archive as its dependency, with all eight internal packages redirected to the packed archives. It declares no framework/compiler/tool dependencies and retains pnpm's normal automatic peer installation behavior. Verify every physical package in its pnpm store is one of the eight Morfira archives, explicitly reject React/Vue/Svelte/Angular bindings, and import the facade in a Node subprocess without DOM globals. This checks the core import and optional peer metadata without using the framework-rich fixture as evidence. The report records `frameworkFreeCoreConsumer: true`, installed package versions and the resolved facade path. Cleanup shares the runner's owned temporary root. The Angular 22-only profile skips this repeated default assurance.

The default profile uses the installed root Angular 21 / TypeScript 5.9 toolchain and exercises five adapters in three browsers (15 scenarios). `pnpm run consumers:check -- --angular22` selects the separately installed private `apps/angular22-consumer` Angular 22 / TypeScript 6 toolchain, retaining the root compiler version for normal builds. The Angular 22 profile checks its supported Node range before packing: Node 22 >=22.22.3, Node 24 >=24.15.0, or Node 26. The normal pnpm invocation must use that Node executable as well.

Both profiles pack the same eight libraries, resolve all public exports from installed tarballs, pin every actual installed toolchain edge and verify an identical isolated graph. Source root lookup additionally permits the private profile's own node_modules binding directory; final dependency realpaths still must remain in the repository node_modules store. This explicit private-directory exception does not permit global/loader fallbacks or source aliases. Compiler framework versions must match the selected major and Angular 22 must resolve TypeScript 6 rather than silently falling through to the root compiler.

Both profiles run ngc in full application compilation mode and link published partial Angular declarations through the official Angular Babel linker with jitMode:false. No runtime JIT compiler is imported by the consumer. The Angular-only profile builds only angular.html and runs three Angular browser cases, leaving unrelated framework compilers out of its temporary dependency graph. The default profile also performs normal TS/Vue/Svelte checks and builds every fixture. Separate reports are artifacts/consumer-packages.json and artifacts/consumer-angular22.json, including profile, source toolchain, archive hashes and browser/compiler versions.

The U3a public-option smoke temporarily mounts a second ready controller with `overflow: 'more'` into a narrow external host. Each wrapper checks its native disclosure and labelled region, dismisses it by Escape, and disposes the temporary UI without changing content/history or the existing controller. This checks the installed options, JavaScript and CSS together; detailed priority, selection and lifecycle boundaries remain in the dedicated editor suite rather than a duplicated adapter matrix.

The optional fonts entry is explicitly installed in the consumer application, not added to default presets. Its public types/commands apply one configured family and size inside one composed transaction to selected text and restore the original content with one Undo. All wrapper fixtures resolve the actual exported tarball entry; detailed CSS filtering, pending typing and configuration matrices remain in the feature suite.

The list-properties smoke explicitly installs the optional entry, creates an ordered list through the existing formatter, then composes start/reversed/marker commands into one change and one Undo. A second Undo restores the pre-list document. Verify actual OL attributes/CSS from installed packages across all wrappers; detailed list targeting, codec and structural numbering barriers remain feature tests.

The text-direction smoke explicitly installs its public optional entry, applies RTL to a selected ordinary block, checks actual dir/computed direction and unchanged text/alignment, and undoes that one revision. It preserves the existing fixture/history before later operations. Detailed target, codec, native bidi and mixed/reset behavior remains in the feature suite rather than a new adapter matrix.

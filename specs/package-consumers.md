# Isolated package consumer verification

Status: accepted tooling contract. This checks installable package artifacts, not source aliases or npm publication. It adds no runtime/editor dependency. Angular compilation/linking tools remain development-only.

The runner requires an existing successful library build. It packs the eight libraries (core, plugins, Vue, React, Svelte, Angular, Web Component and facade) into real tarballs and creates a temporary consumer outside the pnpm workspace. Its dependency and pnpm workspace override entries point to those tarballs. Framework/compiler/bundler versions (including tsx, the runner’s existing tool and an explicitly installed Vite optional peer) and their transitive dependency edges are pinned to the actual installed repository graph. Version-qualified parent>child pnpm overrides preserve multiple compatible package versions instead of globally forcing one version. The runner bounds candidate directories and resolved paths to each graph’s own node_modules before accepting a package; loader/global lookup fallbacks are ignored. Peer-only edges require a binding in the package’s own node_modules or immediate pnpm peer context, so unrelated inherited/hoisted optional peers are recorded as absent instead of being imported into the graph. The runner follows each physical package context, fails on missing required dependencies or ambiguous parent/version edges, and verifies that the isolated installed graph matches before compiling. Uninstalled optional peers are recorded; uninstalled platform-specific optional dependencies must already have exact versions, otherwise the runner fails rather than guessing a resolution. Installation uses pnpm 11.0.7 with `--offline`; a missing cached dependency fails explicitly instead of fetching from npm or silently using workspace links.

The default consumer owns normal Vue SFC, React StrictMode, Svelte 5, Angular 21 and Web Component examples. It imports supported facade/adapter/plugin/CSS exports without TypeScript paths or Vite aliases, type-checks TS/TSX, Vue and Svelte, then creates a production build. Installed package and entry realpaths must remain within the isolated consumer node_modules; artifact versions and archive hashes are recorded. The check must not publish, modify manifests or install packages in the repository.

The React example includes a StrictMode wrapper; a production build does not exercise development-only effect replay (covered separately by the project adapter suite). Browser acceptance uses the built consumer in Chromium, Firefox and WebKit: real typing survives controlled feedback; a structural slash action produces one final change and supports history/following input; external values do not emit user changes; reactive read-only blocks input but accepts an external value; unmount removes editor and optional menus and disposes its API. Browser failures and page errors fail the run. These are recorded smoke scenarios, not broad mobile/IME/accessibility certification.

The runner binds an ephemeral localhost port, closes pages/browsers/server and removes its owned temporary directory in finally. A JSON report under ignored artifacts records package/tool versions, archive hashes, resolved artifact locations, the root lockfile SHA256, exact toolchain edge overrides/absent optional packages and actual browser results. No unstable timing assertion or registry availability is part of acceptance.

## Angular compiler profiles

Before the default browser consumer is installed, a separate minimal temporary consumer declares only the facade archive as its dependency, with all eight internal packages redirected to the packed archives. It declares no framework/compiler/tool dependencies and retains pnpm's normal automatic peer installation behavior. Verify every physical package in its pnpm store is one of the eight Morfira archives, explicitly reject React/Vue/Svelte/Angular bindings, and import the facade in a Node subprocess without DOM globals. This checks the core import and optional peer metadata without using the framework-rich fixture as evidence. The report records `frameworkFreeCoreConsumer: true`, installed package versions and the resolved facade path. Cleanup shares the runner's owned temporary root. The Angular 22-only profile skips this repeated default assurance.

The default profile uses the installed root Angular 21 / TypeScript 5.9 toolchain and exercises five adapters in three browsers (15 scenarios). `pnpm run consumers:check -- --angular22` selects the separately installed private `apps/angular22-consumer` Angular 22 / TypeScript 6 toolchain, retaining the root compiler version for normal builds. The Angular 22 profile checks its supported Node range before packing: Node 22 >=22.22.3, Node 24 >=24.15.0, or Node 26. The normal pnpm invocation must use that Node executable as well.

Both profiles pack the same eight libraries, resolve all public exports from installed tarballs, pin every actual installed toolchain edge and verify an identical isolated graph. Source root lookup additionally permits the private profile's own node_modules binding directory; final dependency realpaths still must remain in the repository node_modules store. This explicit private-directory exception does not permit global/loader fallbacks or source aliases. Compiler framework versions must match the selected major and Angular 22 must resolve TypeScript 6 rather than silently falling through to the root compiler.

Both profiles run ngc in full application compilation mode and link published partial Angular declarations through the official Angular Babel linker with jitMode:false. No runtime JIT compiler is imported by the consumer. The Angular-only profile builds only angular.html and runs three Angular browser cases, leaving unrelated framework compilers out of its temporary dependency graph. The default profile also performs normal TS/Vue/Svelte checks and builds every fixture. Separate reports are artifacts/consumer-packages.json and artifacts/consumer-angular22.json, including profile, source toolchain, archive hashes and browser/compiler versions.

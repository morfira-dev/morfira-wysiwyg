# Optional search and replacement form

The host must be outside the persisted editor surface: the surface itself and every descendant are rejected before creating view DOM, listeners or subscriptions. Rejection preserves document, selection and history.

Status: implementation contract; the search plugin and document schema remain unchanged.

`createSearchForm(host, editor, options?)` requires an installed search plugin before mounting any DOM. It returns `element`, `refresh`, `getValues`, `setValues`, `destroy`. Values are copied drafts `{ query, replacement, caseSensitive, wholeWord }`; options provide partial initial values, an explicit accessible form label and a diagnostic `onError` callback. Invalid value types reject atomically. Public commands on a disposed controller reject; destroy is idempotent and detached controls are inert.

Find submits the query/options to the plugin and selects its first match. Until Find, query/options remain drafts. If they differ from the indexed plugin state, navigation and replacement controls are disabled rather than applying a replacement to stale results. Replacement text is a separate draft. Previous/next wrap using the plugin API; replacements use indexed matches, never the unrelated native selection inside a form field. Replace all remains one undoable plugin operation. Clear explicitly clears search state and resets query/options while retaining replacement text. Creating or destroying UI does not clear application-owned search state.

Plugin state subscriptions update counts, overflow and navigation availability. External query/options synchronize into idle controls; updates while the form is focused do not overwrite the user's drafts. Ordinary document replacement/undo/redo uses the plugin's recomputed index. Find/navigation/clear are available read-only; replacement controls are disabled and guarded in handlers. Locale changes update feature-owned RU/EN labels/status through `ui.search.*` keys while preserving drafts and indexed state. Application labels/errors are not interpreted as HTML; diagnostics go to the optional callback, while user-facing failures are generic localized messages.

The root is a section with accessible `role="form"`, not a nested HTML form; all buttons have type button. Enter in the query performs Find; Enter in replacement performs the guarded current-match replacement. These input keys prevent native submission and stop propagation into an enclosing application's form handler, while composition/legacy-229 keys remain available to the IME. The UI does not submit or persist the surrounding application form.

Acceptance Chromium/Firefox/WebKit: rich-text literal search and real selected result; query/options drafts and disabled stale replacement; current/all replacement and undo; replacement over a different native selection; read-only navigation and external values; live locale/overrides and draft preservation; invalid-query/replacement recovery without document/history corruption; two instances, editor/form cleanup and detached controls; missing-plugin pre-mount failure and import safety without DOM.

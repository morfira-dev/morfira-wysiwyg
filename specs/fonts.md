# Optional font family and text size

Status: first optional fonts slice implemented and verified locally. Actual browser, package-consumer and generated size results belong to verification-backlog.md; the contract below describes its supported scope.

## Scope and storage

Expose the independent `@morfira-dev/wysiwyg/plugins/fonts` entry with `fonts(options?: FontsOptions): EditorPlugin` and `fontCommands(editor): FontCommands`. It is opt-in, not installed by default in presets, and adds no mandatory UI/CSS or runtime dependency. Core never imports the plugin. The small common codec/inline-formatting additions belong to core so HTML/JSON, pending typing, history and selection reuse the same validated operations rather than a second editing engine.

Schema v1 gains support for safe `font-family` style values on its already allowed HTML elements. Existing `font-size` import units/range are unchanged; the command profile below is deliberately narrower. Safe imported font values survive without this plugin and independently of its configured choices. Older readers may strip font-family; this additive capability does not imply lossless older-reader compatibility or a document version change. Rendering, string serialization, native snapshots and HTML/JSON/API/paste boundaries use the same codec validation.

Family values have at most 256 characters and eight comma-separated names. Accept bounded plain ASCII CSS identifiers/simple multiword names and simple single/double-quoted names, plus generic families. Preserve name case, normalize insignificant whitespace/quotes consistently and reject empty parts, controls, escapes, comments, functions/parentheses, declaration delimiters and CSS-wide keywords. This is a documented subset, not a complete CSS font parser. Do not permit URLs, var(), arbitrary declarations or executable/foreign content. Invalid imported declarations are filtered by the existing style contract; malformed document structures still reject atomically. Config/command validation rejects invalid arguments before any edit.

Canonical values use lowercase unquoted generic names, simple non-generic identifiers without quotes and double quotes for multiword non-generic names. An explicitly quoted generic name remains quoted because it denotes a named font rather than the generic family. The pure family validator stays internal to the codec; plugin configuration reuses the existing public `createDocumentSchema().validateDocument` method with one ordinary span style and rejects raw declaration delimiters before wrapping. Construct that default codec once per configuration validation, without DOM. Do not expose an internal helper as a new core API merely for plugin convenience.

The plugin creates no style/link/font-face/FontFace objects, font requests or global registry. It uses installed/system fonts or fonts already provided by the application. A browser may fetch a font previously declared by application CSS when text starts using it; applications own those assets, CSP and licensing. Frontend validation does not replace server-side document validation.

## Options, commands and state

`FontsOptions` contains optional `families: readonly FontFamilyOption[]` and `sizes: readonly number[]`. A family has `id`, `label`, `family`; IDs are unique lowercase ASCII identifiers (1–64 characters, start with a letter, then letters/digits/hyphens), labels are nonempty bounded plain text (at most 100 characters), and family strings pass the shared codec. Each configured list has 1–32 distinct choices. Reject unknown options, duplicate IDs/family values/sizes and malformed records. Copy configuration so later application mutations cannot change an installed instance.

Defaults are IDs `system`, `serif`, `monospace` with families `system-ui, sans-serif`, `Georgia, serif`, `monospace`; default sizes are `[12, 14, 16, 18, 24, 32, 48]`. Configured sizes are integers 8–96 px. Explicit options replace the corresponding default list.

`FontCommands` provides `setFamily(id: string | false): void`, `setSize(size: number | false): void` and `getState(): FontState`. Setters accept only configured IDs/sizes or false. `FontState` is a fresh snapshot: `disabled: boolean`, `family: string | false`, `size: string | false`, `familyMixed: boolean`, `sizeMixed: boolean`. Family/size are actual explicit CSS values, not IDs or computed theme values; safe imported values need not belong to configured choices. Canonicalize family values read from browser CSSOM with the same pure codec before state/mixed/pending comparisons: engines may omit quotes around multiword names without changing their meaning. Missing properties report false. Mixed flags correspond to core formatting snapshots. Public named types are explicitly exported from the entry and kept in owned type files.

Commands use per-editor typed registry tokens, active native selection and the existing read-only/composition guards. Wrong arguments throw atomically; disabled actions do not change selection/content/history/redo. Missing installation and retained handles after disposal throw. Release registrations/provided API on disposal; no observer or event listener is needed for this behavior-only plugin.

Core recognizes `fontFamily` and `fontSize` inline style formats. Family uses the bounded codec; size uses existing safe CSS length validation. Selected formatting retains marks, links, other styles, unselected text and block/list/cell structure with one history operation. Reset false removes only the chosen inline property, preserving other styles; inherited block styles and application theme defaults remain inherited. Collapsed formatting sets pending styles without adding history until text is typed. Preserve effective styles with Undo/Redo, reset them on selection/external replacement and retain rollback/stale-expanded-selection behavior. Empty/edge ranges use the existing inline formatting profile; no arbitrary structural replacement is implied.

## Delivery and acceptance

Use explicit configured dropdown/apply/reset controls and active/mixed state in the homepage/playground laboratory; preserve native selection through external controls. Keep fonts opt-in in the demo's plugin composition and out of default preset graphs. Publish RU/EN API/options/defaults, examples, import compatibility, security/font-loading and unsupported syntax. Ready-toolbar builtins/overflow groups are not extended in this slice.

Representative Chromium/Firefox/WebKit regressions cover: partial rich/backward selection and independent resets/Undo; pending caret styles and real typing/Undo/Redo; a cross-block/list/merged-cell representative and mixed state; HTML/JSON/paste round trips and concrete malformed font CSS with inert codec/no plugin-triggered requests; invalid configuration/commands with rollback and redo retention; read-only/IME/external replacement, per-instance choices and disposal. Avoid a Cartesian product of every font, size and container. Two localized docs smoke cases exercise public controls, native selection/history and responsive layout rather than repeat the core matrix.

Build declarations/selective imports/public facade and real installed tarball consumers. Add a small feature-specific ceiling of 8000 gzip JS bytes for the fonts entry closure (in addition to the existing 150000 gzip optional-entry envelope): configuration and guarded commands need no rendering/font-processing engine. Measure core delta and deduplicated selected profiles as raw/gzip/Brotli JS and CSS separately; do not raise core/profile/adapter budgets. Framework runtimes and application font assets are excluded and explicitly reported separately when provided. Run project check, docs build/tests and consumers; report actual checks and limitations.

# Continuous integration — bounded feedback time

Status: accepted optimization contract. The updated user target (2026-11-18) is at most seven minutes for the complete ordinary CI/release cycle, including the optional Telegram notification. A local configuration or extrapolation is not proof of GitHub wall time; record actual follow-up runs separately. GitHub queue time, registry availability and external npm/Telegram latency remain outside a workflow runtime guarantee. The user explicitly authorized the CI correction, commit, push and observation through publication; local tests are not authorized for this correction.

## Measured baseline and decision

GitHub run 43732191886, commit 43b4408, completed successfully in 37 minutes 41 seconds. Its check job took 35 minutes 31 seconds: `pnpm run check` 29m13s, of which 3591 Playwright executions with two workers took 28.4 minutes; static/build/type work took approximately 46 seconds. Browser installation took 49s, release-tool tests 11s, default packed consumers 60s, Angular 22 consumers 28s, docs build 37s (including another package build) and docs browser tests 176s. Release plan/publish added 33s/93s, including the release build. These are that run's observations, not universal runtime limits.

The first change preserves every unique regression and all Chromium/Firefox/WebKit executions. Split the editor suite into three browser projects × four Playwright shards, each with two workers, on independent runners. Run docs and the two installed-consumer profiles as parallel jobs after one shared build/static job. Expected test time per balanced shard from the observed baseline is around 2m22s, plus setup/artifact overhead; queue/concurrency, runner/browser differences and imbalance can increase this. Do not promise five minutes before measuring a new GitHub run. Do not delete tests or weaken browser/security/merged-grid/lifecycle coverage merely to meet a wall-clock target.

## Workflow graph and boundaries

Keep the reusable Check workflow used by Release and pull_request updates. Remove the duplicate non-main push trigger: it otherwise starts a second complete graph for every open-PR update and can queue up to thirty downstream jobs. Provide workflow_dispatch for a branch without a PR; such branches no longer run the full graph automatically. Cancel superseded PR/manual checks, while main publication remains noncanceling. Its build/static job installs pnpm 11.0.7 with a frozen lockfile, runs project and release/consumer-tooling guards, builds all packages once (retaining the early facade declaration pass needed by the Angular fixture and removing its redundant late repetition), checks declarations/package boundaries/tree-shaking/bundle budgets and runs all TypeScript/Vue/Svelte checks. Publish the built package outputs and required Angular browser/SSR fixtures as a commit-specific artifact. All browser/consumer/docs jobs install dependencies from the same lockfile and consume that exact artifact; no package rebuilds or source-alias replacements in these jobs.

Artifacts must retain original repository paths, including all eight packages' complete dist outputs, playground/angular/dist, artifacts/angular/server.mjs, and the generated size report where needed. Temporary docs/consumer output cannot race with the editor suite: each matrix job owns its own checkout, ports and test-results. Only the selected editor browser needs installation on a shard; docs needs Chromium and installed-consumer profiles retain all three engines. Browser/cache changes must use exact installed Playwright-version/platform keys, not a stale incompatible browser archive. Dependency caching is optional performance tooling, never a correctness prerequisite.

The editor matrix uses explicit `--project`, `--shard=n/4`, `--workers=2`, fullyParallel and no retries/skips added for speed. Independent failed shards must not silently disappear through fail-fast. Docs uses the existing complete bilingual suite with explicit workers; build the site from prebuilt libraries via a separate named `docs:build:site` script, preserving the current `docs:build` all-in-one local command. Consumer jobs retain actual isolated tarball coverage for every adapter and Angular 21/22. Full local `pnpm run check` remains supported; expose a static-only script for the shared CI stage rather than rewriting the local full-check meaning.

A stable aggregate `check` job must fail when any required build/editor shard/docs/consumer job fails, is canceled or unexpectedly skipped. A skipped downstream job after an upstream failure is not success. Release must wait on that complete aggregate through the reusable-workflow dependency, not publish after only the build or one browser. Preserve release version/lock sync and OIDC/publication contracts. Under the 2026-11-18 revision, publish restores the exact commit-specific checked-build artifact from the current successful workflow run in a clean checkout instead of rebuilding it: these are the same outputs consumed by the browser/consumer jobs. Do not restore release payloads from a dependency cache, a different run or an unchecked commit. The read-only release dry-run may run alongside Check, but publish still needs both successful jobs. PR/non-main workflow cancellation may discard superseded checks, but must not cancel a publication already running on main. Set useful per-job timeouts without turning expected queue time into a claimed runtime guarantee.

Use unique failure artifact names per browser/shard/job so parallel uploads cannot conflict. Keep user diagnostics and generated reports available on failures. No additional runtime dependencies, global Node-module cache, package lockfile or Git publication.

## Browser provisioning revision — 2026-11-18

[Run 44326726625](https://github.com/morfira-dev/morfira-wysiwyg/actions/runs/44326726625), including its second attempt, exceeded job timeouts while `playwright install --with-deps` downloaded system libraries from `us-east-2.ec2.archive.ubuntu.com`. Successful jobs in the same run establish that the complete suite was not responsible for those apt delays. Avoid per-job apt and browser downloads: editor, docs and consumer jobs use the official `mcr.microsoft.com/playwright:v<installed-version>-noble` job container, including its preinstalled browser revisions and system libraries. Read the exact installed `@playwright/test` version after the frozen install in the shared build job and expose the image as a job output; never use `latest` or select a different Playwright version to make an image resolve. The official v1.65.0-noble manifest was available when implementing this correction. Future dependency upgrades must have a corresponding image; an unavailable image fails rather than silently switching binaries.

Set `PLAYWRIGHT_BROWSERS_PATH=/ms-playwright` explicitly, keep Node 24 and pinned pnpm, and use `--init --ipc=host` for the test containers. The image serves only local editor/documentation fixtures; no production credentials belong to test jobs. The runtime packages and the complete three-engine/four-shard matrix remain unchanged, with two workers and no new retries or skips. Plan/publish use the pnpm dependency cache; publication retains its separate OIDC-enabled job and fixed npm CLI.

Acceptance is an actual successful GitHub run with no `playwright install`/apt stage, every required shard and consumer profile passing, successful npm publication/version persistence, and a verified Telegram delivery log. Record build/setup/test/release wall times, and distinguish the seven-minute target from the observed result. Local tests, builds and dry-runs are deliberately not run for this correction at the user's request.

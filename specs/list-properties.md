# Optional list properties

Status: first accepted implementation contract; verification belongs to actual runs in verification-backlog.md.

## Scope and persisted data

Provide the independent `@morfira-dev/wysiwyg/plugins/list-properties` entry: `listProperties(): EditorPlugin`, `listPropertyCommands(editor): ListPropertyCommands`, and explicit public `ListMarker`, `ListPropertyCommands`, `ListPropertyState` types. Keep it opt-in and out of preset defaults and ready-toolbar built-ins. No runtime dependencies, stylesheet, listeners, observers or external counter engine.

Operate on one ordinary existing UL/OL container. Start numbering uses the existing signed-32-bit `ol.start` contract. Add `ol.reversed` as a native boolean attribute: HTML presence (including `reversed="false"`) means true and normalizes to `reversed=""`; absent means false. JSON accepts only the canonical empty string on OL, rejecting wrong tags, nonstrings or nonempty values before mutation. Older/default readers from before this feature may discard reversed/marker styles; schema remains v1 with explicit additive compatibility limits.

Add only a bounded `list-style-type` CSS enum on UL/OL: UL accepts `disc`, `circle`, `square`; OL accepts `decimal`, `lower-alpha`, `upper-alpha`, `lower-roman`, `upper-roman`. Canonicalize case/outer whitespace to lowercase. Reject functions, URLs, var(), custom counters, strings, escapes and arbitrary declarations for this property. Imported unsupported/wrong-kind marker declarations are filtered under the existing style policy; other supported styles remain. Do not add deprecated HTML type attributes, li.value, @counter-style, list-style-image or per-item marker commands. HTML/JSON/native snapshots, paste, string rendering and history share the codec, independently of plugin installation.

## Commands and state

`setStart(value: number | false): void` accepts signed-32-bit integers or false (remove explicit start), and enables only on OL. `setReversed(value: boolean): void` sets/removes the native attribute on OL only. `setMarker(value: ListMarker | false): void` accepts the enum or false (remove only explicit marker), enabling only when the marker matches the selected list kind. Public setters validate payloads before registry eligibility, so wrong payloads throw even with no supported selection. A valid command on an unsupported target/kind is a no-op before entering a transaction, preserving pending formatting, focus, redo/content/selection. Registry handlers retain their own validation and target checks. Use per-editor typed command tokens and existing validated synchronous transactions with read-only/composition guards. Actual changes produce one user change and one Undo; composing commands in editor.transact produces one combined revision. Setting an already-present value produces no change/history.

`getState(): ListPropertyState` returns a fresh `{ disabled, kind, start, reversed, marker }`: `kind` is `'ordered' | 'bullet' | false`; start is the explicit integer or false, reversed is boolean, marker is the explicit enum or false. Disabled reflects target eligibility plus read-only/composition; start/reversed require `kind === 'ordered'` in addition. Values describe stored container properties, not computed CSS, inherited markers or an inferred starting number. In particular an omitted start remains false even though the browser supplies normal/reversed defaults. State reads do not change native selection or document/history. Missing installation and retained handles after disposal throw; cleanup releases registrations and provided state.

## Selection and mutation boundaries

Resolve the innermost list for each native Range endpoint. An endpoint on UL/OL itself targets that container, not its outer owner; an endpoint inside an LI targets its immediate containing UL/OL. Both endpoints and the target list must share the same closest td/th boundary (or all have none); selecting text inside a nested table cannot style an outer list outside that cell. Support carets, backward ranges, several direct sibling items, empty LI and list-level DOM offsets. Endpoints in owning semantic nodes, owning list/item ancestors, foreign namespaces, outside the editor, root offsets, other lists/levels or other cells disable the command. A supported list has only direct ordinary HTML LI children and formatting whitespace; malformed direct children are atomic barriers. Validate that shallow target before mutation, without scanning/rebuilding nested branch bodies.

Change only attributes/style on the actual list node; preserve actual item/text/branch nodes, task metadata, unrelated list attributes/styles, order, exact native range/direction and cell ownership. Properties apply to the whole resolved container even when only some items are selected. Descendant attributes are untouched; native CSS inheritance still follows the browser. Do not split/coalesce/retag lists or move items as a property operation. Reuse existing history; Undo/Redo restore original/native selection and subsequent typing. No-op/barrier/invalid operations must not clear pending caret formats or redo.

## Interaction with existing structural editing

Existing shallow list clones keep persisted properties. Core list coalescing/indent reuse must not automatically merge an ordered container when either candidate has explicit start or reversed: such joining changes an independently specified numbering boundary. Unconfigured lists retain existing coalescing; compatible marker styles participate through the existing style comparison. Conversion between UL/OL keeps other safe styles but removes a marker enum incompatible with the new kind; start/reversed are not transferred to a newly created UL. Neither this plugin nor structural commands recalculate numeric offsets for split fragments, continued numbering, reverse item counts or manual counter values: native numbering follows retained attributes and current children. Describe this limit explicitly rather than imply full numbering fidelity for arbitrary transformations.

## Acceptance, examples and size

Representative Chromium/Firefox/WebKit cases: combined properties on a rich backward/multi-item selection with actual subtree identity and one Undo/Redo; nested/empty/list-offset resolution and a merged-cell isolation example; native Enter or indent plus stored-property preservation and explicit-numbered join barriers; HTML/JSON/paste plugin-independent round trips, reversed presence/canonical JSON and concrete CSS/attribute injection/malformed boundaries; invalid payloads/no-op/redo/pending retention; read-only/IME/external replacement, independent instances and stale handles; SSR imports with no DOM/network. Avoid multiplying every marker/start/selection combination; use representative boundary values.

# Replacement across list bodies and sibling items

Status: accepted implementation contract for a bounded local slice. Current execution results, generated bundle measurements and remaining limits are recorded in [verification-backlog.md](verification-backlog.md). Document version 1 and public API/imports remain stable; optional ordered-list start validation and older-reader losses follow [document-attributes.md](document-attributes.md).

## Source ownership

Core owns noncollapsed cancelable `beforeinput` for `insertText` with a string payload, `deleteContentBackward` and `deleteContentForward` when a range spans distinct `li` siblings under one ordinary `ul` or `ol`, or distinct ordinary body blocks within one supported item. The same source ownership applies to detached clipboard/API import preflight. List instances and their attributes stay intact; no global list coalescing pass is introduced.

The default native/ordinary insertion inspector requires direct inline content or a nonempty sequence of ordinary `p`/`h1`–`h6` bodies followed by optional trailing lists. Block payload insertion has the explicitly scoped opaque-quote source extension below; it does not broaden that default inspector. Body children are text, strong/em/u/s/sub/sup/a/span/code/br; inline semantic metadata is preserved. Mixed direct inline/block content, formatting whitespace alongside wrapped bodies, images outside opaque quotes, figures, tables and preformatted blocks remain unsupported. The chosen list, item and ordinary body wrappers must not carry `data-mw-node`; these are defensive guards, not a claim that SDK v1 can register ul/ol/li semantics. An unchanged semantic ancestor outside the chosen list/items is not retagged or removed.

Endpoints inside a wrapped body retain their exact inline context. Item-level offsets between body blocks normalize a start endpoint to the following body's start, and an end endpoint to the preceding body's end. Offset zero maps to the first start and the body-count offset to the final end; offsets into trailing branches are blocked. This uses a cloned working Range and never changes the global selection before the transaction snapshot. Undo restores original item-level or backward selection boundaries rather than normalized coordinates.

Ownership is tri-state:

- Neither endpoint belongs to a list item: unowned; the ordinary-block or existing insertion path retains responsibility. A whole list enclosed by outside endpoints is not normalized by this contract.
- Both endpoints belong to the same body: native typing/deletion and inline/single-paragraph insertion remain unowned. API/clipboard insertion with multiple significant roots including a block candidate, one heading-shaped root or one blockquote-shaped root explicitly opts into the same-body plan, validating the entire item and payload before mutation. This includes a collapsed caret and invalid mixed, semantic multi-root, heading-root or quote-root candidates so they cannot fall through to generic insertion. Endpoints in distinct supported bodies of one item are owned by this contract.
- Exactly one endpoint is in an item, or endpoints belong to different lists/parents: blocked before mutation. This does not define mixed list/paragraph replacement or cross-level list deletion.
- Distinct siblings in one list are eligible only when all their own bodies meet the direct-inline or ordinary-block-sequence shape, with the explicit paste-only quote extension below for structural payloads. Unsupported covered bodies, semantic roots and partial nested selections are blocked atomically rather than delegated to native deletion.

For native/ordinary ranges spanning distinct items, left and middle covered items cannot contain nested lists; the structural quote-crossing profile below explicitly preserves their trailing branches. The rightmost item may contain only trailing direct `ul`/`ol` branches after its body sequence, and its range end must be at or before that sequence's end. Those branches are wholly unselected; move the actual branch nodes to the retained first item after its surviving bodies without flattening, joining, renumbering or stripping their attributes/metadata. Same-item body replacement preserves that item's trailing branches. Content after a nested branch makes the shape unsupported. Replacement entirely inside a nested list uses the same sibling policy and preserves all outer ancestors. Formatting-only whitespace nodes between covered sibling items are fully selected gaps and are removed; non-whitespace or other non-item gap nodes block the operation.

## Result and imported payload

Preserve the actual first item, all its blocks preceding the start body, the actual start wrapper and its untouched inline prefix. Join the end body's inline suffix into that start body; preserve all following right-item body blocks as actual nodes after the joined body, before retained branches. Remove only selected intervening bodies/items. With same-item replacement keep that item and its wholly unselected trailing branches. Unrelated siblings, parent list attributes, cell geometry and ancestor DOM identity remain. Direct and wrapped bodies may be mixed; the first body's kind wins, except a direct inline start is promoted into an ordinary p when surviving following blocks require a block sequence. Its actual inline descendants are moved, never cloned. Insert plain input literally in the starting inline context and place the caret immediately after it. An empty retained body gets one placeholder inside its wrapper. Retained branches remain outside wrappers.

Clipboard/API payloads accept inline content (including allowed incoming img), one ordinary paragraph whose wrapper is removed, one ordinary `h1`–`h6` or bounded `blockquote` root retained as a separate body, or at least two ordinary `p`/`h1`–`h6` roots with supported inline children. A single-heading, single-quote or multi-block profile may contain formatting-only whitespace around its roots, and a multi-block profile may contain it between roots; remove that whitespace only after validating the whole profile. Mixed inline/block roots, semantic block roots, lists, tables, figures and other structural payloads remain rejected during detached preflight for an owned list range. Inline semantic children retain their metadata. This does not turn pasted paragraphs into multiple items. Plain clipboard newlines remain `br` inside the retained item, following `paste-replacement.md`. Incoming explicit formatting is preserved; an incoming anchor must not be nested inside an existing starting anchor.

For a multi-block payload, keep the actual starting body, its tag/attributes and inline prefix. Insert only the first incoming body's inline children in the original starting affinity, ignoring that incoming wrapper's tag/attributes. Retain the subsequent incoming wrappers and attributes as body siblings within the retained first item. The final incoming body receives the original right inline suffix, with the caret between the incoming content and suffix. Preceding source blocks, following right source blocks and wholly unselected trailing branches remain outside the replacement; append following source blocks after the incoming bodies and branches after all bodies. A direct-inline starting item is promoted into an ordinary `p` whenever this block sequence requires it, even if no right source bodies survive. No nested p/h or new li is introduced. First/final incoming empty-body placeholder br is removed before its join; middle empty bodies retain one editable placeholder. Each empty resulting edge body gets one internal placeholder, and the final insertion caret stays before its placeholder when no inline suffix remains.

At a collapsed caret, that same multi-block composition splits only the current body's inline content: preserve its prefix in the retained starting wrapper and move its suffix to the final incoming body. Keep preceding/following source bodies and trailing branches unchanged. Item-level positions between bodies resolve once to the following body's start, and the final body-count position to the last body's end; use that same body and point for both cut edges. Positions beyond the body sequence into trailing branches are blocked rather than clamped. Original text, body, li and placeholder coordinates are recorded before normalization so undo restores the exact original caret. Source empty-body placeholder br is removed at either side of the caret without deleting semantic inline metadata or branch placeholders. Inline/single-paragraph payloads, other single structural roots, plain text and native input keep their earlier ownership rules.

A single ordinary heading has its own splice contract at a caret or over a same-body, same-item or sibling-item selection. Retain the actual starting body with its prefix and tag/attributes, insert the validated heading as a separate sibling with its own tag/attributes and inline children, then insert a suffix body containing the original end body's inline suffix. The suffix wrapper is a shallow clone of that original ordinary paragraph/heading; for a direct-inline end item create an ordinary p instead. A direct-inline start is promoted into an ordinary p. Empty prefix/suffix edge bodies retain one editable placeholder; an empty incoming heading also receives one. The caret starts in the suffix body before the original remainder, or before its placeholder when empty. For `Al|pha` plus `<h2>Title</h2>`, the result is `<p>Al</p><h2>Title</h2><p>pha</p>` with the caret before `pha`. Following source bodies and branches remain after the suffix. There are no new li nodes, nested p/h nodes, or dropped preceding/following blocks. Native input, inline/single-paragraph insertion and other single structural roots retain their earlier paths; a semantic or malformed single heading is rejected before mutation rather than delegated to generic insertion.

Parse/render/sanitize before the outer live edit. Empty sanitized fragments remain no-ops even for an otherwise blocked source; the preflight does not unwrap an ordinary p, so a surviving empty p is still an intentional empty replacement. Invalid public API imports throw; clipboard import rejection remains a no-op. Nested import failure poisons an enclosing transaction even when caught, as in `transactions.md`. Recheck actual source ownership before the live cut because trusted focus listeners may change selection after preflight.

A single ordinary blockquote uses the same standalone splice as a single heading: actual prefix body, validated quote wrapper with its attributes, then a shallow clone of the original end body's wrapper holding the suffix (ordinary p for a direct-inline source). The caret starts in the suffix before its remainder or placeholder. The quote accepts either supported inline children, including incoming images and inline semantic metadata, or a nonempty sequence of ordinary p/h1–h6 children with supported inline content. For the latter profile, formatting whitespace around and between those children is removed only after whole-payload validation. Empty inline quotes receive one br, and empty quote child blocks receive an internal placeholder. Mixed inline/block content, semantic quote or direct child-block roots, nested quotes, lists, tables, figures and preformatted quote children are rejected atomically, including at collapsed and same-body positions. A single blockquote candidate always opts into preflight so invalid quotes cannot fall through to generic insertion.

Block API/clipboard insertion has a paste-only source extension for existing ordinary quotes. A supported p/h body sequence may contain validated ordinary blockquotes as opaque siblings before trailing lists. The source quote uses the incoming quote profile, including inline images and inline semantic metadata; semantic quote/child-block roots and malformed/nested structures reject the whole item before mutation. This opt-in applies only to a multi-root block candidate, single heading or single quote candidate. Inline/single-paragraph insertion, native replacement and keyboard boundary planners retain their earlier inspection rules.

For outer-item paste, endpoints normally belong to ordinary p/h or direct-inline bodies. An item-level position resolving to a quote is blocked rather than clamped to neighboring text. The quote-crossing profiles below permit bounded intervals through ordinary quotes within one item or consecutive sibling items in one ordinary list. Cross-parent/cross-level ranges and partial nested branches remain atomic refusals. Quotes before the starting body remain actual nodes in place; wholly unselected quotes after the ending body move as actual following siblings after the replacement and before trailing lists. Retain quote tag/attributes/content and DOM identity without cloning, unwrapping or coalescing. Multiple untouched quotes are supported.

Repeated quote, heading and multi-block insertion at the resulting ordinary suffix is supported through the same transaction/preflight path. Ordinary suffix typing and exact history remain supported. Native structural deletion through quotes and arbitrary structural source replacement remain outside this slice.

Block API/clipboard insertion inside one ordinary direct-child quote of a list item accepts at least two ordinary p/h payload roots or one ordinary heading. The outer item must still meet the paste-only source profile, including the bounded interleaved-source inner profile below. Both endpoints stay inside that same quote; endpoints in different ordinary quotes within the same item follow the separate crossing profile below. The source quote contains direct inline content or a nonempty ordinary p/h sequence, with source inline images excluded by the existing editable-body guard. Semantic roots, mixed/nested structures and unsupported source bodies reject the whole inner operation. Native input and inline/single-paragraph insertion retain their previous paths. A new quote payload inside an existing quote rejects rather than creating nesting.

Keep the actual quote wrapper, attributes, untouched inner bodies and every outer block/list branch. Inline quotes receive an ordinary p for their retained prefix when block siblings require it. Composition stays inside that quote: multi-block payloads append their first children to the prefix and receive the old suffix in their last body; one heading keeps a standalone wrapper between prefix and cloned suffix bodies, with the caret at the suffix start. Empty edge bodies receive internal placeholders. Quote-level DOM offsets use actual childNodes including formatting gaps: a start maps to the following body's start, an end to the preceding body's end, and the final offset to the last body's end. A collapsed point uses the same normalized body/point for both edges. Original DOM coordinates remain in history. Only formatting gaps wholly covered between selected inner bodies are removed; untouched gaps remain actual nodes. Successful collapsed inner insertion clears pending caret formatting after the transaction snapshot; refusal preserves it.

## Paste across quote boundaries within one item

A noncollapsed block API/clipboard range may cross one or more ordinary quotes directly owned by the same list item. Endpoints may be outside bodies, one ordinary quote and an outside body, or two different ordinary quotes; quotes fully enclosed between the endpoints are removed with covered ordinary bodies. Both endpoints inside the same quote continue to use the inner composition above. Cross-item quote ranges follow the sibling profile below; cross-level ranges and endpoints in nested branches remain barriers. Item-level endpoints resolving to a quote are not reinterpreted as an inner endpoint. Validate every complete affected quote using the strict editable-source profile (inline or ordinary p/h children, no source images or semantic structural roots), including fully covered quotes; wholly unselected neighboring quotes remain opaque. One unsupported affected quote refuses the complete replacement before mutation.

This distinct structural profile accepts the existing valid multi-p/h, single-heading and single-quote payloads. Keep every incoming root's tag, attributes and supported inline content as standalone siblings at the item level: no first/last payload wrapper is merged with the quote or the source prefix/suffix. A new quote payload is a sibling, never a nested quote. Inline/single-paragraph paste and native input retain their earlier ownership rules.

Keep the actual starting wrapper and inline prefix: an ordinary outside body or a clipped starting quote with its actual endpoint body and preceding quote children/gaps. Keep the actual ending wrapper and inline suffix: an ordinary outside body or a clipped ending quote with its actual endpoint body and following quote children/gaps. Remove fully selected intervening bodies and quotes. Insert every incoming root as a sibling between these retained wrappers. If the ending wrapper is a quote, add a new empty p with one br after the payload and before the quoted remainder, with the caret at that paragraph start. Otherwise place the caret at the actual outside suffix body start. For quote-to-different-quote replacement, retain both actual quoted edge wrappers and their unselected descendants; the payload stays outside both quotes.

Empty retained endpoint bodies receive an editable placeholder inside their existing wrapper; an emptied partial quote retains its wrapper and editable endpoint body. Empty incoming bodies receive placeholders under the existing payload rules. Unselected source bodies, quoted children, formatting gaps and trailing list branches retain their DOM identity and order. Do not create list items, flatten a quote, coalesce quotes or move content across a branch. Inspect source, endpoint normalization and payload completely before live mutation. Use the existing transaction, exact forward/backward selection history and pending-format clearing; no public API/schema or native-input expansion is introduced.

## Paste through quotes in consecutive sibling items

A noncollapsed structural block API/clipboard selection may span consecutive sibling items in one ordinary ul/ol when at least one quote occurs in the affected body interval. Endpoints may belong to ordinary wrapped/direct-inline bodies or direct ordinary quotes. Inspect every selected item before mutation. In this quote-crossing profile, preserve trailing branches of first, intermediate and final items as actual subtrees, including branches under wholly covered intermediate items. Newly accepted first/intermediate branch roots must be ordinary direct trailing ul/ol without data-mw-node; imported validated descendants remain opaque and retain their actual structure and metadata. The final-item branch profile is unchanged. Items with ordinary wrapped bodies after branches use the ordered quote-crossing profile below; the trailing-only profile retains its established placement rules. Different parents/levels, branch endpoints, non-item gaps, semantic/unsupported shapes and LI endpoints resolving directly to quotes remain atomic barriers. Strictly validate every affected quote, including fully covered middle-item quotes; wholly unselected neighboring quotes keep the opaque validation profile. The no-affected-quote sibling path keeps its existing composition rules.

Retain the actual first item and its attributes, preceding bodies and clipped starting body/quote. Retain the actual final body/quote with its clipped suffix, subsequent final-item bodies/opaque quotes and trailing branch nodes, moving them in order into the first item. Remove the selected tail of the first item, fully covered middle items, the consumed final item and fully selected formatting-only inter-item gaps. Keep unrelated sibling items, list attributes, table geometry and ancestor identity. Promote a direct-inline endpoint item's actual remaining descendants into an ordinary p before composing block siblings; never insert an li inside another li or let trimming consume retained branch placeholders.

Detach every retained branch before trimming direct-inline roots or removing covered bodies/items. Append all preserved branches after the complete resulting body sequence, in source-item order (first, intermediate items, final item) and original order within each item. Do not merge, flatten, retag or clone the branch roots or their descendants; preserve list attributes, nested structure and actual DOM identity. This deliberate relocation preserves branch-to-branch order rather than claiming the original interleaved body/branch depth-first reading order. Native, inline/single-paragraph and structural sibling replacement without an affected quote keep their previous branch barriers.

Keep every incoming multi-p/h, single-heading or single-quote root as a standalone first-item child between preserved source edges. Both partially selected quotes and their endpoint bodies/unselected children/gaps keep identity. When the right edge stays quoted, add a fresh editable pBR after the payload and before that quote, with the caret at its start; otherwise use the preserved outside suffix body's start. Preserve empty edges with placeholders. Use the existing atomic transaction, exact original forward/backward selection history, pending-format clearing and guards. Same-item, native and inline/single-paragraph ownership is unchanged.

## Ordered quote crossing with blocks after branches

A separate structural API/clipboard profile applies when at least one selected item contains an ordinary wrapped p/h/quote after a direct nested list. The interleaved item starts with a wrapped body and contains only ordinary wrapped bodies/validated quotes and ordinary direct ul/ol roots; loose inline content mixed with wrappers and branch-first shapes remain unsupported. Neighboring noninterleaved items may keep their existing direct-inline shape. Every branch root in the selected items is an ordinary HTML ul/ol without data-mw-node; validated descendants remain opaque actual subtrees. The range must cross distinct own body roots with at least one affected quote, in one item or consecutive sibling items under one parent. A same-body/collapsed range outside a quote in an interleaved item, native input, inline/single-paragraph insertion and ranges without an affected quote remain blocked by the old source boundary. Ranges or carets inside one ordinary quote follow the separate inner profile below.

Keep all actual children before the start body in the first item in their original sequence, including prefix branches. Retain the actual clipped start and end body/quote wrappers. Put every validated incoming root immediately after the start prefix. Preserve every branch between the source endpoint roots in source item/child order and place these protected interval branches after the payload, before the end suffix. If the suffix is quoted, put a fresh editable pBR after those interval branches immediately before the actual end quote, and place the caret there; otherwise place the caret at the actual outside suffix start. Preserve all children following the last endpoint root in their exact body/list sequence. The result therefore preserves relative order of retained source nodes rather than partitioning all lists after all bodies. Payload comes before protected interval branches. Fully selected own bodies/quotes and consumed items/gaps are removed; branch subtrees are neither cloned, merged nor flattened.

Inspect the complete source, branch roots and every affected quote before mutation. Quote-level gap affinity and strict source validation are unchanged. Item-level endpoints use actual childNodes, never a body-only index that skips lists: a start facing a branch or an end following a branch is blocked rather than clamped to another body. Other ordinary body edges keep exact original coordinates in history. Nested branch endpoints, different parents/levels, semantic/unsupported bodies and roots remain atomic refusals. Detach protected interval branches and any following nodes required to protect direct-inline clipping before clipping/removal; prefix nodes remain in place and the last suffix/following sequence moves as actual nodes under the retained first item. Existing trailing-only quote crossing, native and ordinary composition contracts remain unchanged.

## Paste inside one quote in an interleaved item

The existing inner-quote API/clipboard profile also accepts an owning item with ordinary wrapped blocks after direct nested lists. Both endpoints remain inside one ordinary direct-child quote: a caret, a noncollapsed range within one ordinary quote body or a forward/backward range across its ordinary child bodies. Accept multiple ordinary p/h payload roots or one ordinary heading; a new nested quote, inline/single-paragraph payloads and native input retain their earlier ownership and guards. An interleaved item still begins with a wrapped own body and contains only the validated ordinary wrapped bodies/quotes and direct branch roots; mixed loose content and branch-first structures are unsupported.

Before creating the inner context, validate every direct branch root of that interleaved item as ordinary HTML ul/ol without data-mw-node; imported validated descendants remain opaque. Strictly validate the target quote using the existing editable-source profile, excluding source images, semantic structural wrappers and nested unsupported content. Neighboring quotes retain their existing opaque validation. Reject unsupported sources or payloads before live mutation, preserving original selection, pending formats, DOM identity and history.

Reuse the existing inner composition, not the ordered outer crossing path. The incoming multi-block first body joins the actual prefix body and its last body receives the original suffix; a single heading remains a standalone quote child between prefix and separate suffix bodies. Direct-inline quote contents receive ordinary paragraph wrappers only as required by that existing composition. Keep the actual quote and all outer owning-item children in their exact order and identity, including branches before/after the quote and ordinary blocks following those branches. No branch, outer body, list or item is moved or removed by this inner insertion. Keep raw quote gaps/unselected children, placeholders, quote-level endpoint affinity and exact history coordinates under the existing contract. The caret precedes the original suffix inside the quote; successful collapsed insertions clear pending formats after the history snapshot, and Undo restores them. This extension does not authorize ordinary same-body editing outside the quote or native quote boundary editing.

## History and guards

An accepted replacement is one isolated synchronous transaction/change. Undo restores original HTML and exact forward/backward DOM boundaries, including empty bodies and line breaks; redo restores the result and insertion caret. Subsequent ordinary typing has separate history and retains existing native boundary affinity rather than a new forced formatting state.

Caret-only formatting overrides belong to a collapsed selection, not a later selected range. A valid noncollapsed API/clipboard replacement clears those overrides inside the mutation callback after its original snapshot is captured. It must not retain an old override merely because the replacement's new caret has the same text offset as the earlier collapsed caret. Invalid imports, empty sanitized imports and boundary barriers remain no-ops for that pending state. This does not force the browser's mark inheritance after the replacement.

A successful collapsed multi-block, single-heading or single-quote list insertion also clears pending caret-formatting overrides inside the existing transaction after its original snapshot is captured. This remains necessary when an empty payload leaves the resulting text offset numerically unchanged; explicit incoming formatting and the new body's native affinity take responsibility. Undo restores the original pending formatting and exact caret. Refused or fully stripped payloads preserve pending formatting.

Already canceled events, read-only, composition and noncancelable beforeinput retain existing guards. Unsupported native protocols such as word deletion/replacement targets remain outside this slice. A blocked native operation or detached-preflight refusal before opening the transaction consumes no document/history revision and preserves content, range and unrelated DOM identity. If a trusted focus listener changes the context after preflight, a late fresh-context rejection uses the existing transaction rollback: it preserves the transaction's HTML, selection and history baseline but may rebuild DOM nodes. Unrelated DOM identity is not guaranteed for that late rollback path; this slice does not change the global rollback contract.

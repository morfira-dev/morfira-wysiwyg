# Replacement across list bodies and sibling items

Status: accepted implementation contract for a bounded local slice. Validation is deferred at the user's request: new tests are written but not executed, builds/type checks/size measurements are not run, and the last measured size report remains the earlier paste baseline. Schema v1 and public API/imports are unchanged.

## Source ownership

Core owns noncollapsed cancelable `beforeinput` for `insertText` with a string payload, `deleteContentBackward` and `deleteContentForward` when a range spans distinct `li` siblings under one ordinary `ul` or `ol`, or distinct ordinary body blocks within one supported item. The same source ownership applies to detached clipboard/API import preflight. List instances and their attributes stay intact; no global list coalescing pass is introduced.

Each item owns either direct inline content or a nonempty sequence of ordinary `p`/`h1`–`h6` bodies followed by optional trailing lists. Body children are text, strong/em/u/s/sub/sup/a/span/code/br; inline semantic metadata is preserved. Mixed direct inline/block content, formatting whitespace alongside wrapped bodies, images, figures, tables and preformatted blocks remain unsupported. The chosen list, item and body wrappers must not carry `data-mw-node`; these are defensive guards, not a claim that SDK v1 can register ul/ol/li semantics. An unchanged semantic ancestor outside the chosen list/items is not retagged or removed.

Endpoints inside a wrapped body retain their exact inline context. Item-level offsets between body blocks normalize a start endpoint to the following body's start, and an end endpoint to the preceding body's end. Offset zero maps to the first start and the body-count offset to the final end; offsets into trailing branches are blocked. This uses a cloned working Range and never changes the global selection before the transaction snapshot. Undo restores original item-level or backward selection boundaries rather than normalized coordinates.

Ownership is tri-state:

- Neither endpoint belongs to a list item: unowned; the ordinary-block or existing insertion path retains responsibility. A whole list enclosed by outside endpoints is not normalized by this contract.
- Both endpoints belong to the same body: native typing/deletion and inline/single-paragraph insertion remain unowned. API/clipboard insertion with multiple significant roots including a block candidate explicitly opts into the same-body plan, validating the entire item and payload before mutation. This includes a collapsed caret and invalid mixed or semantic multi-root candidates so they cannot fall through to generic insertion. Endpoints in distinct supported bodies of one item are owned by this contract.
- Exactly one endpoint is in an item, or endpoints belong to different lists/parents: blocked before mutation. This does not define mixed list/paragraph replacement or cross-level list deletion.
- Distinct siblings in one list are eligible only when all their own bodies meet the direct-inline or ordinary-block-sequence shape. Unsupported covered bodies, semantic roots and partial nested selections are blocked atomically rather than delegated to native deletion.

For ranges spanning distinct items, left and middle covered items cannot contain nested lists in this slice. The rightmost item may contain only trailing direct `ul`/`ol` branches after its body sequence, and its range end must be at or before that sequence's end. Those branches are wholly unselected; move the actual branch nodes to the retained first item after its surviving bodies without flattening, joining, renumbering or stripping their attributes/metadata. Same-item body replacement preserves that item's trailing branches. Content after a nested branch makes the shape unsupported. Replacement entirely inside a nested list uses the same sibling policy and preserves all outer ancestors. Formatting-only whitespace nodes between covered sibling items are fully selected gaps and are removed; non-whitespace or other non-item gap nodes block the operation.

## Result and imported payload

Preserve the actual first item, all its blocks preceding the start body, the actual start wrapper and its untouched inline prefix. Join the end body's inline suffix into that start body; preserve all following right-item body blocks as actual nodes after the joined body, before retained branches. Remove only selected intervening bodies/items. With same-item replacement keep that item and its wholly unselected trailing branches. Unrelated siblings, parent list attributes, cell geometry and ancestor DOM identity remain. Direct and wrapped bodies may be mixed; the first body's kind wins, except a direct inline start is promoted into an ordinary p when surviving following blocks require a block sequence. Its actual inline descendants are moved, never cloned. Insert plain input literally in the starting inline context and place the caret immediately after it. An empty retained body gets one placeholder inside its wrapper. Retained branches remain outside wrappers.

Clipboard/API payloads accept inline content (including allowed incoming img), one ordinary paragraph whose wrapper is removed, or at least two ordinary `p`/`h1`–`h6` roots with supported inline children. A multi-block profile may contain formatting-only whitespace around and between its roots; remove that whitespace only after validating the whole profile. Mixed inline/block roots, a lone heading, semantic paragraph/heading roots, lists, tables, figures and other structural payloads remain rejected during detached preflight for an owned list range. Inline semantic children retain their metadata. This does not turn pasted paragraphs into multiple items. Plain clipboard newlines remain `br` inside the retained item, following `paste-replacement.md`. Incoming explicit formatting is preserved; an incoming anchor must not be nested inside an existing starting anchor.

For a multi-block payload, keep the actual starting body, its tag/attributes and inline prefix. Insert only the first incoming body's inline children in the original starting affinity, ignoring that incoming wrapper's tag/attributes. Retain the subsequent incoming wrappers and attributes as body siblings within the retained first item. The final incoming body receives the original right inline suffix, with the caret between the incoming content and suffix. Preceding source blocks, following right source blocks and wholly unselected trailing branches remain outside the replacement; append following source blocks after the incoming bodies and branches after all bodies. A direct-inline starting item is promoted into an ordinary `p` whenever this block sequence requires it, even if no right source bodies survive. No nested p/h or new li is introduced. First/final incoming empty-body placeholder br is removed before its join; middle empty bodies retain one editable placeholder. Each empty resulting edge body gets one internal placeholder, and the final insertion caret stays before its placeholder when no inline suffix remains.

At a collapsed caret, that same multi-block composition splits only the current body's inline content: preserve its prefix in the retained starting wrapper and move its suffix to the final incoming body. Keep preceding/following source bodies and trailing branches unchanged. Item-level positions between bodies resolve once to the following body's start, and the final body-count position to the last body's end; use that same body and point for both cut edges. Positions beyond the body sequence into trailing branches are blocked rather than clamped. Original text, body, li and placeholder coordinates are recorded before normalization so undo restores the exact original caret. Source empty-body placeholder br is removed at either side of the caret without deleting semantic inline metadata or branch placeholders. Inline/single-root payloads, plain text and native input keep their earlier ownership rules.

Parse/render/sanitize before the outer live edit. Empty sanitized fragments remain no-ops even for an otherwise blocked source; the preflight does not unwrap an ordinary p, so a surviving empty p is still an intentional empty replacement. Invalid public API imports throw; clipboard import rejection remains a no-op. Nested import failure poisons an enclosing transaction even when caught, as in `transactions.md`. Recheck actual source ownership before the live cut because trusted focus listeners may change selection after preflight.

## History and guards

An accepted replacement is one isolated synchronous transaction/change. Undo restores original HTML and exact forward/backward DOM boundaries, including empty bodies and line breaks; redo restores the result and insertion caret. Subsequent ordinary typing has separate history and retains existing native boundary affinity rather than a new forced formatting state.

Caret-only formatting overrides belong to a collapsed selection, not a later selected range. A valid noncollapsed API/clipboard replacement clears those overrides inside the mutation callback after its original snapshot is captured. It must not retain an old override merely because the replacement's new caret has the same text offset as the earlier collapsed caret. Invalid imports, empty sanitized imports and boundary barriers remain no-ops for that pending state. This does not force the browser's mark inheritance after the replacement.

A successful collapsed multi-block list insertion also clears pending caret-formatting overrides inside the existing transaction after its original snapshot is captured. This remains necessary when an empty payload leaves the resulting text offset numerically unchanged; explicit incoming formatting and the new body's native affinity take responsibility. Undo restores the original pending formatting and exact caret. Refused or fully stripped payloads preserve pending formatting.

Already canceled events, read-only, composition and noncancelable beforeinput retain existing guards. Unsupported native protocols such as word deletion/replacement targets remain outside this slice. A blocked native operation or detached-preflight refusal before opening the transaction consumes no document/history revision and preserves content, range and unrelated DOM identity. If a trusted focus listener changes the context after preflight, a late fresh-context rejection uses the existing transaction rollback: it preserves the transaction's HTML, selection and history baseline but may rebuild DOM nodes. Unrelated DOM identity is not guaranteed for that late rollback path; this slice does not change the global rollback contract.

Acceptance tests cover real typing and deletion plus beforeinput-only dispatch, both list kinds, nested lists and merged cells, literal inline HTML/plain paste, rich suffix/links, empty/br/Unicode boundaries, preserved trailing branches, list attributes, controlled feedback, guards and atomic rejections. These test definitions are not evidence of a passing run until the deferred validation is performed. No runtime dependency, CSS, public export, engine rewrite or performance claim is introduced.

Multi-body acceptance additionally covers forward/backward same-item replacement, item-level offsets spanning a selected body interval, preceding/following block identity, preservation of empty nested branch placeholders, sibling-item replacement whose endpoints are interior bodies, direct-inline promotion with continued typing and undo, semantic later-body barriers, API/clipboard payload refusal and merged-cell ancestor identity. These scenarios are written in `tests/list-multiblock-selection.spec.ts` but remain unexecuted.

Multi-block payload acceptance additionally covers API/clipboard replacement between items, between bodies in one item and within one body; direct-inline promotion; incoming heading/paragraph attributes; whitespace-separated roots; rich prefix/suffix affinity and anchors; empty first/middle/final bodies; preserved following blocks/branches; exact backward/LI endpoints and one-step history; unsafe or structural payload refusal; guards, nested transaction rollback and React controlled feedback. Definitions remain unexecuted under the deferred verification policy.

Collapsed multi-block acceptance additionally covers start/middle/end carets in direct inline, paragraph and heading bodies; item-level gaps and the final body edge; source placeholders before/after br; rich/Unicode/link suffixes; actual preceding/following body and branch identity; nested lists/merged cells; same-offset pending-format clearing and undo restoration; atomic source/payload barriers and controlled adapter feedback. These are written scenarios, not executed browser evidence.

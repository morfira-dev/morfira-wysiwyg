# Editor contract — document schema v1

Status: implemented preview contract. Acceptance scenarios are exercised in `tests/editor.spec.ts` and `tests/native.spec.ts`; verification limits remain explicit.

## Requirements

- Core/plugins are original TypeScript with no runtime dependencies. Functions use const arrow declarations. License: MIT.
- Public facade, framework imports, and plugin subpaths remain stable. The prototype's engine escape hatch and persisted operation format are intentionally replaced; no automatic document-format migration is promised.
- Persist `EditorDocument { version: 1, children: DocumentNode[] }`. Text and allowed semantic element nodes carry only validated attributes. HTML and JSON imports enforce schema, URLs, attribute/style allowlists, and resource limits. Unsupported executable or foreign content is omitted. Invalid JSON is rejected before live DOM mutation.
- Instance API: HTML/text/JSON get/set; text-offset selection; formatting; insertHTML; read-only; focus; own undo/redo; atomic plugin transactions; subscriptions and disposal. No external engine escape hatch or browser execCommand.
- Native typing and IME composition use the browser editing surface; our bounded history records semantic revisions with selection bookmarks. New edits clear redo; external document replacement clears history. IME is one history operation.
- History bookmarks at an empty text node preserve its parent boundary, because HTML snapshots omit empty text nodes. Redo after inserting a link in an empty block must leave subsequent typing after the link.

- Formatting must preserve unaffected text, support partial removal and cross-paragraph selections, and restore selection. Document operations must be atomic on failure.
- Paste replaces selection using validated HTML or plain text; unsupported drops are blocked. Read-only prevents user/programmatic user-edit commands while allowing external replacement.
- Every instance owns listeners and plugin APIs. Destroy is idempotent and performs all cleanup even when a disposer fails. Imports are safe to evaluate during SSR; createEditor requires browser DOM.
- Vue v-model, React controlled value including StrictMode, and Svelte bind:value share document/change semantics. External replacement emits no adapter feedback event. Same-value feedback preserves caret.

Composition event ordering, interim edits, command guards and cancellation follow `specs/composition.md`. Ordinary paragraph/heading Enter and boundary deletion follow `specs/block-boundaries.md`. Noncollapsed typing/deletion across ordinary sibling leaves follows `specs/input-replacement.md`; unsupported structural and cross-container selections retain their existing input paths.

HTML/API insertion and clipboard replacement across those ordinary sibling leaves follow `specs/paste-replacement.md`. Incoming data is prepared before the outer live edit; inline, ordinary multi-block and structural payload composition have distinct documented boundaries. This does not establish general structural source selection, nested-table support or Office paste fidelity.

The subsequent bounded list-item replacement contract is `specs/list-selection.md`; collapsed body-boundary deletion and wrapped-body Enter/Shift+Enter follow the addendum in `specs/lists-toolbar.md`. Items may contain direct inline content or a sequence of ordinary paragraphs/headings followed by optional nested lists. Selection replacement preserves blocks before and after the selected body range. Enter splits the item and moves subsequent bodies and branches into the new item. Interior Delete/Backspace joins adjacent bodies. Semantic body wrappers, mixed direct text/block shapes and interleaved branches remain outside these bounded operations. Owned list operations must reach guarded beforeinput without being intercepted by legacy list/block keydown handlers. This new local list slice is unverified: execution of tests, builds, type checks and size measurements is deferred at the user's request, with the remaining evidence recorded in `specs/verification-backlog.md`. Previous ordinary-block results do not validate these new paths.

## Acceptance scenarios

A single ordinary blockquote is a standalone list insertion profile at a caret or over supported selections: actual prefix body → preserved incoming quote → suffix wrapper cloned from the original end body (p for direct-inline content), with the caret before the suffix. Incoming quote children may be inline content or an ordinary p/h sequence; semantic block roots, mixed children and nested structures are atomic refusals. Surrounding source blocks/branches and empty editable edges are retained. Successful collapsed quote insertion clears pending caret formats after the transaction snapshot and restores them on undo. A paste-only source planner permits repeated block profiles in ordinary bodies before/after existing validated quotes, retaining those quotes as actual opaque nodes. A structural selection crossing or covering one ordinary quote in a single list item follows the crossing profile below; intervals affecting multiple quotes or crossing items remain atomic refusals. Native/boundary commands and inline/single-paragraph paste keep their existing source rules; full editing of quote bodies is not implied. Validation is deferred.

Within one ordinary quote directly owned by a list item, a paste-only context accepts multiple ordinary paragraphs/headings or one ordinary heading at the caret or across its own child bodies. Keep the actual quote wrapper, its outer item and branches; compose prefix/payload/suffix inside that quote. Inline source quotes receive ordinary paragraph wrappers when block siblings require them. Resolve quote-level DOM offsets using actual child nodes and formatting gaps, preserving original history coordinates. New nested quote payloads, semantic source roots, source images, unsupported structures and different-quote ranges are atomic refusals; the single-item crossing profile below handles quote-to-outside ranges. Pending caret formats and exact selection participate in the existing transaction/history. Native quote input and other payload profiles remain unchanged; validation is deferred.

Structural block paste across one ordinary quote boundary in one list item preserves each incoming paragraph, heading or standalone quote wrapper as an item-level sibling. Outside-to-quote ranges retain the actual quoted suffix and add an editable unquoted paragraph before it, with the caret at that paragraph start. Quote-to-outside ranges retain the actual quoted prefix and place the caret at the preserved outside suffix start. Outside-to-outside ranges covering exactly one validated quote remove that quote and preserve both outside edge bodies. Partial quote wrappers and unaffected descendants retain identity and order. Invalid source shapes, multiple affected quotes, different quotes, item/branch crossings and unsupported payloads reject atomically. This paste-only contract does not extend native boundary editing. Regression definitions and bilingual examples are added with execution deferred.

A single ordinary incoming h1–h6 is a separate list-body insertion profile: retain the actual source prefix body, then the incoming heading with its tag/attributes, then a suffix body cloned from the original end wrapper (ordinary p for a direct-inline item). Keep edge bodies editable even when empty and put the caret at the suffix body's start. Apply this to collapsed carets and supported selections, preserving surrounding blocks and branches within the retained item. Semantic heading roots and malformed heading payloads are rejected before mutation, including same-body/collapsed contexts; valid collapsed insertion clears pending caret formats inside the existing transaction after its snapshot. Inline/single-paragraph insertion and the multi-block composition rules remain unchanged. This local profile is unverified.

List HTML insertion additionally accepts a sequence of at least two ordinary paragraph/heading payload blocks under `list-selection.md`. Preserve the start body's tag/attributes and inline prefix, insert the first payload's children there, retain subsequent payload wrappers and join the original suffix into the final payload body. Surviving following bodies/branches remain outside payload wrappers. Direct-inline starts receive an ordinary paragraph when block siblings require it. This paste-only extension owns noncollapsed same-body list selections and collapsed positions in supported list bodies. At an item-level boundary the caret resolves to the following body's start, or the final body's end before branches. Native typing/deletion and inline/single-paragraph insertion retain their existing paths. A successful collapsed multi-block insert clears pending caret formats inside the transaction after its original snapshot; undo restores them with the original DOM point. Invalid/empty imports and barriers preserve that pending state. Structural/mixed and semantic multi-root payloads remain rejected before live mutation. Validation is deferred.

Collapsed Backspace at a supported multi-block item's first body follows the first-body contract in `lists-toolbar.md`: join the preceding sibling item's final body, unwrap the first root item into its actual body blocks, or lift the first nested item one level with its following siblings retained as a trailing branch. When the source is not the owner's final branch, move later validated owner branches under the lifted item after its own branches and retained source siblings; earlier owner branches remain untouched. Preserve depth-first content order without merging lists. Validate every affected container before changing DOM; preserve body/branch content, exact history and cell boundaries. This local extension remains unverified under the same deferred-check policy.

1. Select part of a sentence, toggle bold on/off, undo/redo and recover exact text and selection. Existing neighboring formats remain intact.
2. Type text, undo a burst, redo; branch with a new edit and verify redo is empty. Replace external content and verify previous document cannot be undone.
3. Paste safe rich text over a selection. Script markup, event handlers, unsafe URLs, arbitrary CSS, SVG/MathML and malformed JSON cannot enter an executable DOM.
4. A throwing transaction leaves content/history unchanged; a throwing plugin setup leaves no mounted view or listeners.
5. Each adapter mounts, accepts external value, emits a user change, changes read-only, and unmounts without duplicate subscriptions or views.
6. Core can be imported in a Node process without DOM globals; runtime dependency maps for core/plugins remain empty.

## Verification limits

Browser tests establish their recorded scenarios, not full Word/Excel fidelity, complete browser editing normalization, accessibility conformance, collaborative editing, or mobile/IME certification. Report those separately.

Caret regression: disabling an inline mark in the middle of marked text keeps the insertion position, preserves the mark on both neighboring fragments, and retains other nested marks.

Lists, keyboard boundaries and toolbar extensions follow `specs/lists-toolbar.md`. Document schema v1 is unchanged.

Inline color and enhanced link commands follow `specs/colors-links.md`. Invalid link command arguments now throw before mutation, replacing the earlier silent rejection; safe HTML/JSON imports still sanitize through schema v1.

Image commands follow `specs/images.md`. Schema v1 adds figure/figcaption semantics; older readers may flatten those wrappers. Image commands remain an optional module.

Optional literal find/replace follows `specs/search.md`, with no schema change or core dependency on the search entry. Replacements retain document structure and participate in history; search/navigation do not.

Optional Markdown typing rules follow `specs/markdown-shortcuts.md`. Conversions are transactions over schema v1; shortcuts do not run during import/paste or composition.

History snapshots retain bounded pending caret formatting (boolean marks and inline colors) with their collapsed text offset. Undo/redo restores this transient affinity only when the restored caret still matches that offset, so subsequent text after a Markdown conversion remains outside the newly closed mark after redo. This metadata is history-only, never HTML/JSON schema data. External replacement and ordinary selection movement still clear pending formatting. Failed transactions restore pending formatting with their document/selection snapshot.

Phase-1 suggestions follow `specs/mentions-slash.md`: @label and slash snippets are ordinary editable text inserted in one transaction. Schema v1 has no mention IDs/atoms; structural slash commands now follow the separate phase-2 action registry contract and use composable transactions. Optional menu DOM stays outside persisted surface and cleans up with controller/editor disposal.

Typed instance events and synchronous command composition follow `specs/events.md` and `specs/transactions.md`. Core stays independent from plugins; source ownership and selective-import guarantees follow `specs/code-organization.md` and `specs/modularity.md`.

# Editor contract — document schema v1

Status: implemented preview contract. Current browser, build, type and generated bundle evidence, together with remaining verification limits, is recorded in [verification-backlog.md](verification-backlog.md). Acceptance scenarios describe the supported contracts rather than universal editor compatibility.

## Requirements

- Core/plugins are original TypeScript with no runtime dependencies. Functions use const arrow declarations. License: MIT.
- Public facade, framework imports, and plugin subpaths remain stable. The prototype's engine escape hatch and persisted operation format are intentionally replaced; no automatic document-format migration is promised.
- Persist `EditorDocument { version: 1, children: DocumentNode[] }`. Text and allowed semantic element nodes carry only validated attributes. HTML and JSON imports enforce schema, URLs, attribute/style allowlists, and resource limits. Unsupported executable or foreign content is omitted. Invalid JSON is rejected before live DOM mutation.
- Instance API: HTML/text/JSON get/set; text-offset selection; formatting; insertHTML; read-only; focus; own undo/redo; atomic plugin transactions; subscriptions and disposal. No external engine escape hatch or browser execCommand.
- Native typing and IME composition use the browser editing surface; our bounded history records semantic revisions with selection bookmarks. New edits clear redo; external document replacement clears history. IME is one history operation.
- History bookmarks at an empty text node preserve its parent boundary, because HTML snapshots omit empty text nodes. Redo after inserting a link in an empty block must leave subsequent typing after the link.

- Formatting must preserve unaffected text, support partial removal and cross-paragraph selections, and restore selection. Document operations must be atomic on failure.
- Paste replaces selection using validated HTML or plain text; unsupported drops are blocked. Read-only prevents user/programmatic user-edit commands while allowing external replacement.
- Every instance owns listeners and plugin APIs. Destroy is idempotent and performs all cleanup even when a disposer fails. Imports are safe to evaluate during SSR; createEditor requires browser DOM.
- Vue v-model, React controlled value including StrictMode, and Svelte bind:value share document/change semantics. External replacement emits no adapter feedback event. Same-value feedback preserves caret.

Ordered-list `start` is an additive optional attribute on the existing schema-v1 `ol` tag. Its validation and older-reader numbering-loss limits follow [document-attributes.md](document-attributes.md); preserving document version 1 does not promise lossless attribute support in older readers.

The optional [list-properties](list-properties.md) slice adds native `ol.reversed`, bounded per-kind UL/OL marker styles and commands scoped to one existing container. Shared codec support persists those properties without the plugin. Existing structural editing keeps list attributes but does not automatically coalesce explicit-numbered OL containers or recalculate numbering offsets across split fragments; the bounded contract does not introduce li.value or a counter engine.

The optional [text-direction](text-direction.md) slice adds bounded block/container dir persistence and explicit LTR/RTL/reset commands independently from alignment. Shared codec support is plugin-independent; older readers may discard the additive attribute. Ordinary clone/retag/list/Markdown preservation and directed-list merge boundaries follow that contract without introducing an automatic bidi engine.

Composition event ordering, interim edits, command guards and cancellation follow `specs/composition.md`. Ordinary paragraph/heading Enter and boundary deletion follow `specs/block-boundaries.md`. Noncollapsed typing/deletion across ordinary sibling leaves follows `specs/input-replacement.md`; unsupported structural and cross-container selections retain their existing input paths.

HTML/API insertion and clipboard replacement across those ordinary sibling leaves follow `specs/paste-replacement.md`. Incoming data is prepared before the outer live edit; inline, ordinary multi-block and structural payload composition have distinct documented boundaries. This does not establish general structural source selection, nested-table support or Office paste fidelity.

The subsequent bounded list-item replacement contract is `specs/list-selection.md`; collapsed body-boundary deletion and wrapped-body Enter/Shift+Enter follow the addendum in `specs/lists-toolbar.md`. Items may contain direct inline content or a sequence of ordinary paragraphs/headings followed by optional nested lists. Selection replacement preserves blocks before and after the selected body range. Enter splits the item and moves subsequent bodies and branches into the new item. Interior Delete/Backspace joins adjacent bodies. Semantic body wrappers and mixed direct text/block shapes remain outside these bounded operations; interleaved branches have only the structural quote-crossing profile below. Owned list operations must reach guarded beforeinput without being intercepted by legacy list/block keydown handlers. Current list-editing acceptance evidence and remaining coverage limits are recorded in [verification-backlog.md](verification-backlog.md); results for one editing profile do not establish arbitrary structural support.

## Acceptance scenarios

A single ordinary blockquote is a standalone list insertion profile at a caret or over supported selections: actual prefix body → preserved incoming quote → suffix wrapper cloned from the original end body (p for direct-inline content), with the caret before the suffix. Incoming quote children may be inline content or an ordinary p/h sequence; semantic block roots, mixed children and nested structures are atomic refusals. Surrounding source blocks/branches and empty editable edges are retained. Successful collapsed quote insertion clears pending caret formats after the transaction snapshot and restores them on undo. A paste-only source planner permits repeated block profiles in ordinary bodies before/after existing validated quotes, retaining those quotes as actual opaque nodes. A structural selection crossing or covering ordinary quotes within one item or consecutive sibling items follows the crossing profile below; cross-list and cross-level intervals remain atomic refusals. Native/boundary commands and inline/single-paragraph paste keep their existing source rules; full editing of quote bodies is not implied.

Within one ordinary quote directly owned by a list item, a paste-only context accepts multiple ordinary paragraphs/headings or one ordinary heading at the caret or across its own child bodies. Keep the actual quote wrapper, its outer item and branches; compose prefix/payload/suffix inside that quote. Inline source quotes receive ordinary paragraph wrappers when block siblings require them. Resolve quote-level DOM offsets using actual child nodes and formatting gaps, preserving original history coordinates. New nested quote payloads, semantic source roots, source images and unsupported structures are atomic refusals; the crossing profile below handles quote-to-outside and different-quote ranges within one item or eligible sibling items. Pending caret formats and exact selection participate in the existing transaction/history. Native quote input and other payload profiles remain unchanged.

Structural block paste across one or more ordinary quotes in one list item preserves each incoming paragraph, heading or standalone quote wrapper as an item-level sibling. Every affected quote passes strict editable-source validation, including wholly covered quotes. Preserve the actual partially selected start/end quote wrappers, their endpoint bodies and unaffected children/gaps; remove fully selected intermediate quotes and bodies. Outside-to-quote and different-quote ranges retain the actual quoted suffix and add an editable unquoted paragraph before it, with the caret at that paragraph start. Ranges ending outside a quote place the caret at the preserved outside suffix start. Outside-to-outside ranges covering quotes remove those quotes and preserve both outside edge bodies. Retain empty endpoint bodies with editable placeholders. Invalid affected source shapes, unsupported branch crossings, LI endpoints resolving directly to quotes and unsupported payloads reject atomically. Same-quote inner composition and native/inline paths are unchanged.

Across consecutive sibling items in the same ordinary list, structural quote-crossing paste keeps the actual first item, preceding blocks and start prefix. Move the actual last endpoint wrapper with its suffix, following last-item blocks/opaque quotes and trailing branches under that first item in order; remove covered tails, intervening items, the last item and fully selected formatting gaps between items. For this quote-crossing structural profile, retain trailing branch subtrees from every selected item. Detach all branches before clipping, direct-inline promotion or item removal. Append them after all resulting body blocks in source item order and original per-item branch order: first, intermediate, last. This relocates earlier branches after the result body sequence; preservation of original global body/branch depth-first order is not claimed. Move actual branch roots/descendants without coalescing, flattening, cloning, retagging or changing internal list attributes/empty placeholders. Newly moved first/intermediate branch roots must be ordinary direct trailing ul/ol without semantic ownership; validated descendants remain opaque. Interleaved bodies after branches use the separately scoped ordered profile below; nested endpoint/cross-level ranges and unsupported branch roots reject before mutation. Native and no-affected-quote paths retain their earlier branch barriers. Direct-inline endpoint items receive ordinary paragraph wrappers around actual retained descendants; never nest li inside li or delete branch placeholders. Every affected quote, including fully selected middle-item quotes, passes strict source validation before mutation. Payload wrappers remain independent item-level siblings, with an unquoted pBR caret before a quoted suffix or a caret at the outside suffix start. Same-item and ordinary cross-item composition without affected quotes remain unchanged. Guards, exact forward/backward history and atomic refusal use the existing transaction.

When a selected item has wrapped ordinary bodies or quotes after a direct nested list, a dedicated ordered quote-crossing profile supports distinct endpoint roots in one item or consecutive sibling items. Require at least one affected ordinary quote and ordinary direct branch roots; the interleaved item starts with a wrapped body, with no loose mixed inline content, while noninterleaved neighboring items retain supported direct-inline endpoints. Preserve the first item's prefix child sequence including branches. Insert every incoming root at the selection start, then preserve interval branch subtrees in source order before the actual right suffix. Place an editable pBR immediately before a quoted suffix after those protected branches, or the caret at the outside suffix start. Preserve the exact right-following child sequence, including bodies after lists; remove only covered own bodies/quotes and consumed sibling items/gaps. All retained nodes keep relative order and identity without partitioning following branches into a final group. The previous trailing-only branch profile remains unchanged. Interleaved-source same-body outside a quote, no-affected-quote and native/inline paths remain blocked; the inner-quote structural profile below is the scoped same-quote extension. Item-level endpoints use actual child positions and cannot resolve through a branch. Validate the whole source/payload before mutation; history and guards retain the existing contract.

The existing inner-quote structural paste profile also applies when its owning list item has wrapped blocks after nested lists. A caret or selection within one ordinary direct-child quote composes incoming multi-p/h or one ordinary heading inside that actual quote, preserving the complete outer body/list sequence and actual neighboring nodes. Support same-body and cross-child-body ranges, inline quote promotion and real quote child-node offsets/gaps under the existing inner contract. Validate ordinary branch roots throughout an interleaved owner before mutation; imported branch descendants remain opaque. Source quote structural semantics/images/unsupported nesting and incoming nested quotes reject atomically. Retain empty editable edges, exact selection/history, pending caret formatting and read-only/composition guards. This does not broaden native/inline/single-paragraph insertion or ordinary-body insertion outside the quote. Runtime verification status must be reported from actual runs.

A single ordinary incoming h1–h6 is a separate list-body insertion profile: retain the actual source prefix body, then the incoming heading with its tag/attributes, then a suffix body cloned from the original end wrapper (ordinary p for a direct-inline item). Keep edge bodies editable even when empty and put the caret at the suffix body's start. Apply this to collapsed carets and supported selections, preserving surrounding blocks and branches within the retained item. Semantic heading roots and malformed heading payloads are rejected before mutation, including same-body/collapsed contexts; valid collapsed insertion clears pending caret formats inside the existing transaction after its snapshot. Inline/single-paragraph insertion and the multi-block composition rules remain unchanged.

List HTML insertion additionally accepts a sequence of at least two ordinary paragraph/heading payload blocks under `list-selection.md`. Preserve the start body's tag/attributes and inline prefix, insert the first payload's children there, retain subsequent payload wrappers and join the original suffix into the final payload body. Surviving following bodies/branches remain outside payload wrappers. Direct-inline starts receive an ordinary paragraph when block siblings require it. This paste-only extension owns noncollapsed same-body list selections and collapsed positions in supported list bodies. At an item-level boundary the caret resolves to the following body's start, or the final body's end before branches. Native typing/deletion and inline/single-paragraph insertion retain their existing paths. A successful collapsed multi-block insert clears pending caret formats inside the transaction after its original snapshot; undo restores them with the original DOM point. Invalid/empty imports and barriers preserve that pending state. Structural/mixed and semantic multi-root payloads remain rejected before live mutation.

Collapsed Backspace at a supported multi-block item's first body follows the first-body contract in `lists-toolbar.md`: join the preceding sibling item's final body, unwrap the first root item into its actual body blocks, or lift the first nested item one level with its following siblings retained as a trailing branch. When the source is not the owner's final branch, move later validated owner branches under the lifted item after its own branches and retained source siblings; earlier owner branches remain untouched. Preserve depth-first content order without merging lists. Validate every affected container before changing DOM; preserve body/branch content, exact history and cell boundaries.

1. Select part of a sentence, toggle bold on/off, undo/redo and recover exact text and selection. Existing neighboring formats remain intact.
2. Type text, undo a burst, redo; branch with a new edit and verify redo is empty. Replace external content and verify previous document cannot be undone.
3. Paste safe rich text over a selection. Script markup, event handlers, unsafe URLs, arbitrary CSS, SVG/MathML and malformed JSON cannot enter an executable DOM.
4. A throwing transaction leaves content/history unchanged; a throwing plugin setup leaves no mounted view or listeners.
5. Each adapter mounts, accepts external value, emits a user change, changes read-only, and unmounts without duplicate subscriptions or views.
6. Core can be imported in a Node process without DOM globals; runtime dependency maps for core/plugins remain empty.

## Verification limits

Browser tests establish their recorded scenarios, not full Word/Excel fidelity, complete browser editing normalization, accessibility conformance, collaborative editing, or mobile/IME certification. Report those separately.

Caret regression: disabling an inline mark in the middle of marked text keeps the insertion position, preserves the mark on both neighboring fragments, and retains other nested marks.

Lists, keyboard boundaries and toolbar extensions follow `specs/lists-toolbar.md`. Document schema v1 is unchanged.

Inline color and enhanced link commands follow `specs/colors-links.md`. Invalid link command arguments now throw before mutation, replacing the earlier silent rejection; safe HTML/JSON imports still sanitize through schema v1.

Optional font configuration and commands follow `specs/fonts.md`. Core recognizes validated `fontFamily`/`fontSize` inline properties through common formatting/history; configuration, command handlers and UI choices belong to the independent plugin. Schema v1 adds bounded font-family preservation on existing style-bearing elements; older readers may discard it. Existing font-size import units/range remain unchanged. No font files or font-loading resources are supplied implicitly.

Image commands follow `specs/images.md`. Schema v1 adds figure/figcaption semantics; older readers may flatten those wrappers. Image commands remain an optional module.

Optional literal find/replace follows `specs/search.md`, with no schema change or core dependency on the search entry. Replacements retain document structure and participate in history; search/navigation do not.

Optional Markdown typing rules follow `specs/markdown-shortcuts.md`. Conversions are transactions over schema v1; shortcuts do not run during import/paste or composition.

History snapshots retain bounded pending caret formatting (boolean marks, inline colors and font properties) with their collapsed text offset. Undo/redo restores this transient affinity only when the restored caret still matches that offset, so subsequent text after a Markdown conversion remains outside the newly closed mark after redo. This metadata is history-only, never HTML/JSON schema data. External replacement and ordinary selection movement still clear pending formatting. Failed transactions restore pending formatting with their document/selection snapshot.

Phase-1 suggestions follow `specs/mentions-slash.md`: @label and slash snippets are ordinary editable text inserted in one transaction. Schema v1 has no mention IDs/atoms; structural slash commands now follow the separate phase-2 action registry contract and use composable transactions. Optional menu DOM stays outside persisted surface and cleans up with controller/editor disposal.

Typed instance events and synchronous command composition follow `specs/events.md` and `specs/transactions.md`. Core stays independent from plugins; source ownership and selective-import guarantees follow `specs/code-organization.md` and `specs/modularity.md`.


Controlled Enter and real clipboard paste also expose the bounded, post-validation `inputcommit` receipt specified in [events.md](events.md). The receipt does not modify input/history semantics or turn notifications into a command bus; follow-up plugin changes remain separate validated transactions.


The direct inline-fragment insertion fallback stabilizes its local paragraph/heading/list body after placing the live post-insert range and before capturing history or delivering an input receipt. Native local normalization may merge adjacent Text nodes and remove empty Text nodes; the live caret follows those changes, so Undo/Redo restore its exact logical position between inserted text and the original suffix. Element identity, attributes, rich formatting, content and order remain unchanged. This is limited to non-structural payloads within a connected local block: do not normalize the editor root, unrelated structural siblings, or bypass the existing dedicated replacement/list-paste handlers. Transient Text-node identity is not a persisted document contract.

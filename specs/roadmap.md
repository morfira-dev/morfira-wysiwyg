# Product roadmap

Status: revised development plan. SDK phase 1, P1–P3 behavior presets and U1/U2 modern UI are implemented locally. Remaining milestones describe priorities and acceptance outcomes, not release dates. SDK boundaries follow `specs/plugin-sdk.md`; U3 priority/More overflow and contextual controls remain future work.

Morfira is an independently implemented strict-TypeScript editor under MIT. The product target is a ready everyday-authoring experience close to mature editors in common tasks, with measurable improvements in selected bundle size, extension contracts, UI and documentation. CKEditor, TinyMCE and notectl are comparison references, not implementations to copy. Feature-for-feature enterprise or office-suite parity is not required. Heavy conversion, collaboration and processing remain optional integrations for explicitly requested use cases, outside core. Core/plugins retain zero runtime dependencies; adapters use optional framework peers.

Every milestone follows specification → implementation → browser acceptance → size measurement → RU/EN documentation. Test a defined task/profile before claiming an advantage; smaller JavaScript does not prove faster input, lower history memory, complete accessibility or better compatibility.

## Implemented baseline

- Versioned schema-v1 HTML/JSON boundaries, formatting, selection, bounded history, synchronous composable transactions and instance-local typed events. Contracts: `editor.md`, `transactions.md`, `events.md`.
- Nested lists, colors, alignment and link commands; images with application-owned upload, dimensions, captions and alt text; literal find/replace, Unicode statistics and Markdown typing shortcuts. Contracts: `lists-toolbar.md`, `colors-links.md`, `images.md`, `search.md`, `statistics.md`, `markdown-shortcuts.md`.
- Logical table grid, merged-cell operations, range HTML/TSV clipboard and column sizing. Contracts: `tables.md`, `table-clipboard.md`.
- Editable-text mentions/slash suggestions and structural slash actions. Persistent identity-bearing mentions/atoms are not implemented. Contract: `mentions-slash.md`.
- Per-instance RU/EN localization, translation overrides and live updates. Vue, React, Svelte, Angular 21/22 adapters and an explicitly registered framework-free Web Component. Contracts: `localization.md`, `adapters-angular.md`, `adapters-web-component.md`, `adapters-react-feedback.md`.
- Optional reusable link/image/search UI forms used by the homepage/playground, separate CSS and scoped upload cancellation. Contracts: `ui-forms.md`, `ui-links.md`, `ui-images.md`, `ui-search.md`.
- Feature-owned source organization, selective public imports/tree-shaking, isolated tarball consumer tooling for all five wrappers and observational large-document/history benchmarks. Contracts: `code-organization.md`, `modularity.md`, `package-consumers.md`, `performance.md`.
- Bounded composition and ordinary paragraph/heading keyboard contracts. Real-device OS IME, mobile/touch and screen-reader coverage remain unverified. Cross-block selection replacement requires further normalization. Contracts: `composition.md`, `block-boundaries.md`.

The new bounded list-item replacement and boundary-deletion paths support direct-inline content or several ordinary paragraphs/headings per item. Replacement retains unselected body blocks; wrapped-body Enter splits the item and moves following blocks/branches, while Shift+Enter stays inside a body. Interior Delete/Backspace joins adjacent bodies. These paths are implemented locally but remain **unverified**; semantic body wrappers, mixed text/block shapes and interleaved branches remain outside this slice. Their new tests/examples are written; test execution, builds, type checks and fresh bundle measurements are deferred at the user's request. See `list-selection.md`, `lists-toolbar.md` and `verification-backlog.md`. Do not present the preceding measured paste profile or browser results as evidence for the newer list code.

## Milestones

Single ordinary quote HTML insertion is implemented locally for list carets and supported selections, retaining prefix and suffix bodies around the standalone quote. Quote content accepts inline data or ordinary paragraph/heading children. Repeated block paste in ordinary bodies preserves unselected validated quotes before/after the insertion. Ranges inside/across quotes, native quote boundary editing, nested structural quote content and semantic block payloads remain later work. Written tests and bilingual examples are tracked with deferred validation in `verification-backlog.md`.

Single ordinary heading HTML insertion is implemented locally for list carets and supported selections: prefix body → preserved incoming heading → suffix body, with the caret before the suffix. It preserves item/branch structure and has atomic semantic/malformed heading barriers. Its contract is `list-selection.md`; tests, builds, type checks and sizes remain deferred.

The local list-paste extension accepts at least two ordinary paragraph/heading payload blocks over supported list selections and at a collapsed caret within a supported item. It retains prefix/suffix formatting, unselected blocks and branches within one item and one history operation. Item-level caret boundaries resolve to the following body start or final body end. Pending caret formatting participates in undo without leaking into the new insertion point. Structural and semantic multi-root payloads remain outside this slice. Tests, builds, type checks and fresh sizes are deferred under `verification-backlog.md`.

The local first-body Backspace extension joins a previous item's final body or removes one list level for a first item, preserving multi-block bodies, trailing branches and subsequent items. Nested lift also supports a nonfinal owner branch: later validated branches move after the lifted item's own branches and source siblings, preserving depth-first order; earlier branches remain with the owner. Its specification is `lists-toolbar.md`; tests, RU/EN examples and deferred verification are tracked with the rest of the unverified list work.

1. **Plugin SDK and extensible schema — phase 1 implemented.** Provides per-instance typed command tokens, validated execution/state and declarative schema contributions compiled before initial import. Phase 1 preserves schema v1: safe existing block/inline wrappers carry validated semantic markers and bounded metadata. Acceptance covers isolation, HTML/JSON/native-input round-trip, paste, rollback/history, invalid definitions and read-only/composition guards. See `plugin-sdk.md`. Mapped structural selection, custom node views, atoms, decorations and richer document operations are later SDK slices, not phase-1 claims. A full immutable-engine rewrite is not implicit.
2. **Input correctness and measured history — bounded replacement and paste slices implemented locally.** Same-parent ordinary-block selection replacement follows `input-replacement.md`; clipboard/API text and HTML insertion over these boundaries follows `paste-replacement.md`; registered heading exits and semantic join barriers follow `block-boundaries.md`. Broader structural replacement/deletion, complex selection insertion and text drag/drop remain follow-ups under `input-correctness-next.md`. Expand real-device IME/autocorrect/dictation/mobile coverage. Measure history and locality on fixed large documents before selecting narrower inverse-operation or patch optimizations. Acceptance preserves content/selection/history and records actual device/browser evidence separately from simulated events.
3. **Product UI and ready presets — P1–P3 and U1/U2 implemented locally.** Pure minimal/standard/extended factories, a grouped modern shell, native block/list/alignment/color controls, reusable link/image/search panels and extended suggestion views are implemented locally. Narrow hosts use wrapping. Preserve explicit CSS, per-instance lifecycle, focus and keyboard contracts. U3 measured priority/More overflow and contextual tools remain future work. Contracts: `editor-presets.md`, `editor-ui.md`.
4. **Everyday feature gaps.** Add checklists, broader autolink triggers, font family/size, horizontal-rule command/UI, list properties and text direction. Add small fullscreen/preview/special-character modules and application-owned save-state integration where specified. Font lists are configuration; font files never load implicitly. Each capability requires document round-trip, history, keyboard and selective-import tests.
5. **Images and tables.** Add clipboard/drop image flows, pointer/keyboard image sizing, proportions/alignment and upload progress/error/retry. Improve table insertion picker, table/cell properties, header/caption commands, row minimum heights, accessible resize and contextual UI while preserving merged-grid correctness. Acceptance includes HTML/JSON/clipboard persistence, one-step undo and keyboard-only operation; upload transport remains application-owned.
6. **External paste compatibility.** Maintain real Word, Excel, Google Docs, LibreOffice and browser fixtures with an explicit support matrix. Separate safe default import, plain text and optional Office normalization. Preserve supported lists, styles, links, tables and images; document unsupported losses. Sanitization alone is not evidence of Office fidelity.
7. **Markdown, persistent mentions and search.** Add an independently imported Markdown codec with explicit supported syntax and loss/fallback rules, identity-bearing mention data and atomic selection after the required SDK foundation, and non-persisted highlighting of all search matches. Use the shared command registry for slash actions. Acceptance includes codec fixtures, stable identity/history and no metadata/decorations leaking into exported content unintentionally.
8. **Optional advanced authoring.** Add provider-registry video embeds with click-to-load, a separately imported formula module with a documented format/native MathML scope, and content/print layouts. Specialized resources remain opt-in and separately measured. DOCX/PDF conversion, review and collaboration need their own requested integration scope and size/architecture assessment; they are not implied core work.
9. **Continuous documentation, accessibility and performance.** Each earlier milestone updates RU/EN API, working examples, limits, migrations and bundle reports. Expand plugin-author guides, five-wrapper/SSR/controlled-value recipes, CSP and storage/upload guidance. Maintain visual, keyboard, contrast, zoom, reduced-motion and real screen-reader/device checks. Benchmark identical document/task profiles with explicit input, operation, history-memory and cleanup definitions. This work is continuous, not postponed until all features ship.

Standalone `autolink()` is implemented for native Space completion through `/plugins/autolink`; Enter/paste/import are outside phase 1. It is included by default in the implemented standard/extended presets; a runtime disable flag does not remove its static import graph. Contract: `specs/autolink.md`.

## Size profiles and comparison rules

All sizes below are decimal bytes. Raw means minified JavaScript/CSS, not package archive size. Measure gzip and Brotli separately and count each shared chunk once per selected closure. Framework runtimes, source maps and declarations are excluded; fonts and additional locale alternatives are separate resources.

| Profile | Target or guard | Status |
| --- | --- | --- |
| Core | 80000 raw JS bytes | Working development target |
| Core | 200000 raw JS bytes | Existing enforced hard guard |
| Table entry | 150000 raw JS bytes | Existing enforced hard guard |
| Each adapter | 10000 raw JS bytes | Existing enforced hard guard, framework excluded |
| Standard editor with selected plugins/UI | 200000 raw / 65000 gzip JS bytes | Active measured-profile guard, headless and ready |
| Extended selection | 350000 raw / 110000 gzip JS bytes | Active measured-profile guard, headless and ready |
| Standard/extended CSS | 20000 raw CSS bytes | Active selected-profile guard, headless and ready |

P4 guards are active in `scripts/size.ts` for the measured standard/extended closures; `editor-presets.md` records the lightweight-product reason and profile boundaries. Minimal remains measured without an additional preset guard. A preset must publish its actual feature list and resource/loading boundaries. Do not equate competitors' full distributions with a minimal local core or treat different feature sets as a functional parity benchmark. Tightening guards requires an explained product reason and a measured profile; writing a future target does not change build limits by itself.

## Delivery limits

Current tests do not certify arbitrary Office documents, every mobile/IME input path, accessibility conformance, memory-leak freedom or production readiness. New public API/document changes require explicit compatibility notes and migration decisions. Publication, deployment and Git writes remain separate user-authorized actions; the documentation site remains local-only.

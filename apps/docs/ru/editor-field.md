# Поле редактора в приложении

Соедините существующий адаптер, готовую панель и валидацию с сохранением вашего
приложения. Это прикладной рецепт, а не ещё один пакет редактора. В примере есть
видимая подпись, подсказка, ошибка, read-only, явное сохранение и повтор,
восстановление сохранённого документа и имитация загрузки изображения.

## Попробуйте поле целиком

Удалите весь текст и нажмите **Сохранить публикацию**: поле получит фокус,
появится ошибка, запрос не отправится. В этом примере обязателен непустой текст;
одно изображение не удовлетворяет этому редакционному правилу. Приложение выбирает
собственную проверку содержимого: непустой HTML ещё не означает осмысленный документ.

Введите черновик, сохраните и продолжите ввод, пока видно **Сохранение…**.
Сохранится предыдущий снимок, а новые правки останутся в состоянии **Есть изменения**.
**Последний сохранённый текст** показывает сохранённое содержимое отдельно от
черновика. **Следующее сохранение с ошибкой** отклонит один запрос;
**Повторить сохранение** отправит текущий черновик, а не прежний ошибочный payload.

**Восстановить сохранённое** явно заменяет документ и очищает историю Undo.
Операция отменяет подтверждение текущего запроса: запоздалый ответ не заменит
восстановленный документ. Read-only блокирует редактирование и вставку изображения,
но разрешает сохранить уже подтверждённое содержимое.

**Имитировать загрузку изображения** показывает локальный прогресс и вставляет
логотип сайта. **Отменить загрузку** останавливает запрос. Файл-заглушка не читается
и никуда не передаётся. Форма изображения в готовой панели использует тот же callback:
выбор настоящего локального файла также не отправляет его байты в этой демонстрации.

## Свяжите подпись и ошибку с самим полем

Contenteditable не является нативным элементом, поддерживающим HTML label.
Поместите подпись, подсказку и ошибку в приложение и укажите их уникальные ID
на `editor.surface`. Одних атрибутов внешней обёртки недостаточно, чтобы связать
эти узлы с редактируемым textbox.

Скопируйте небольшой прикладной helper в свой проект: это не npm-subpath. Он
меняет только три принадлежащих ему ARIA-атрибута и восстанавливает их при cleanup,
если другой владелец не успел их изменить.

Создайте рядом файлы `types.ts` и `index.ts`:

<<< @/.vitepress/theme/editor-field/types.ts

<<< @/.vitepress/theme/editor-field/index.ts

Вызывайте `setInvalid(true)`, только пока соответствующая ошибка существует и
актуальна. Пример использует постоянный узел ошибки с `role="alert"`. Подпись,
подсказку и ошибку переводит приложение; `editor.setLocale()` переводит встроенный UI.
ARIA-описание не заменяет валидацию и не разрешает серверные операции.

## Готовая панель и сохранение приложения

```ts
import { createStandardPreset } from '@morfira-dev/wysiwyg/presets/standard';
import { saveState } from '@morfira-dev/wysiwyg/plugins/save-state';
import { createStandardEditorUI } from '@morfira-dev/wysiwyg/ui/standard';
import '@morfira-dev/wysiwyg/style.css';
import '@morfira-dev/wysiwyg/plugins/tables.css';
import '@morfira-dev/wysiwyg/ui/editor.css';
import '@morfira-dev/wysiwyg/ui/forms.css';

// save и upload — типизированные callbacks приложения. Сохраняйте настройки
// неизменными на протяжении mount. Новое поле получает новый bundle.
const preset = createStandardPreset({
  images: { upload },
  plugins: [saveState({ save })],
});

// Передайте preset.plugins адаптеру. После ready:
const ui = createStandardEditorUI(toolbarHost, editor, {
  presentation: 'floating',
  overflow: 'more',
});
// При unmount: ui.destroy(); редактор уничтожит сам адаптер.
```

[Save-state](/ru/save-state) уже управляет запросом на экземпляр, снимками ревизий,
ошибкой, повтором и отменой. Подписывайтесь на его состояние вместо второго dirty-
счётчика. Успешное сохранение старого снимка не помечает последующие правки
сохранёнными. Внешняя замена создаёт новый baseline, а feedback того же HTML
через controlled binding сохраняет выделение и историю.

Локальный сервис намеренно не является рабочим хранилищем. В настоящем `save`
передавайте отдельный документ и условие его версии авторизованному backend,
применяйте AbortSignal к транспорту и подтверждайте только принятый сервером запрос.
Сервер отвечает за авторизацию, валидацию, идемпотентность и конфликты версий.
Отмена клиента не откатывает уже принятый сервером запрос. Не показывайте сырой
ответ ошибки и не вставляйте недоверенный HTML напрямую.

## Подключение через любой адаптер

Используйте публичный ready адаптера для внешнего UI и семантики поля. Храните
cleanup вместе с конкретным mounted-редактором, а не в глобальном singleton.
Значение формы, ID и состояние валидации остаются у приложения.

| Адаптер | Controlled value | Подключение в ready | Cleanup |
| --- | --- | --- | --- |
| Vue | `v-model="value"` | `@ready="onReady"` | `onBeforeUnmount` |
| React | `value={value}` и `onChange={({ html }) => setValue(html)}` | `onReady={onReady}` | cleanup эффекта с поддержкой StrictMode remount |
| Svelte 5 | `bind:value` | `onready={onReady}` | `onDestroy` или cleanup эффекта |
| Angular 21/22 | `[formControl]="body"` или `[(value)]="value"` | `(ready)="onReady($event)"` | `DestroyRef.onDestroy` |
| Web Component | `.value` и `value-change` | `detail` CustomEvent `ready` | удаление listeners и внешнего UI при удалении элемента |

Не совмещайте Angular form binding и отдельного владельца `[value]`. В React
каждое новое ready должно освобождать предыдущую связь: StrictMode может создать
другой редактор. Для Web Component регистрируйте элемент явно только в браузере,
а его свойства задавайте до подключения.

[Полные примеры адаптеров](/ru/adapters) показывают импорт, значение и lifecycle
каждого фреймворка. [Прикладные рецепты](/ru/extension-recipes) содержат сохранение
с проверкой версии и транспорт рабочей загрузки. [Безопасность](/ru/security)
описывает границу frontend/backend.

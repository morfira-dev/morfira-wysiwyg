# Отображение сохранённого контента

Представление контента показывает статью, запись базы знаний или сохранённое поле
без создания редактора. Модуль и scoped-стили подключаются отдельно. Он принимает
JSON схемы v1 из `editor.getJSON()` либо HTML, заново построенный через ту же
границу валидации.

## Сохранение, загрузка и отображение

```ts
import type { EditorDocument } from '@morfira-dev/wysiwyg';
import { createContentView } from '@morfira-dev/wysiwyg/content-view';
import '@morfira-dev/wysiwyg/content-view.css';

// Хранилище и серверная проверка принадлежат приложению.
const saved = editor.getJSON();
const payload = JSON.stringify(saved);
const loaded: unknown = JSON.parse(payload);
const published = createContentView(articleHost);
published.setJSON(loaded as EditorDocument); // решающей остаётся runtime-валидация схемы

// Некорректный JSON вызывает исключение, прежняя статья остаётся на месте.
const independentCopy = published.getJSON();
const normalizedHTML = published.getHTML();
// При удалении экрана приложения:
published.destroy();
```

`articleHost` — подключённый пустой HTML-элемент текущего документа вне
contenteditable. Контроллер владеет одним дочерним article, а не контейнером.
Getters возвращают канонические сохранённые данные независимо от отображения:
у скрытого изображения сохраняются исходный URL и метаданные в JSON/HTML.
Изменение возвращённой JSON-копии не меняет отображённую статью.

## Изображения и переходы по ссылкам

По умолчанию модуль не создаёт IMG и навигационный `href`: вместо изображения
показывается alt-текст, у ссылки остаются текст и форматирование. Простое
отображение не запускает запросы изображений или превью. Это не управление
CSS, шрифтами и другими сетевыми действиями приложения.

Разрешение ресурсов задаётся приложением явно:

```ts
const published = createContentView(articleHost, {
  value: saved,
  images: 'load',
  links: 'navigate',
  imagePlaceholder: '[Изображение]',
  label: 'Опубликованная статья',
});
```

`images: 'load'` может запрашивать изображения, адреса которых разрешаются в http/https.
Относительный src при отображении становится абсолютным, поэтому последующая смена
base не перенаправляет запрос. Для другого протокола остаётся alt-текст.
`links: 'navigate'` сохраняет только разрешённые после разрешения URL назначения
http/https/mailto/tel и открывает их в новой вкладке с
`target="_blank" rel="noopener noreferrer"`. Относительные адреса разрешаются по base URL
документа при отображении; в DOM записывается абсолютный href, поэтому последующая
смена base не перенаправляет ссылку. Исходный сохранённый адрес не меняется. Политику разрешённых origin, CSP и авторизацию загрузок задаёт приложение;
фронтенд-фильтрация не заменяет серверную проверку.

У медиа и формул остаются допустимые исходные обёртки и буквальный текст: модуль
не создаёт iframe-плееры, удалённые thumbnails, MathML или custom node views.
Более сложное отображение подключает приложение отдельно.

## Собственные узлы документа

Если в сохранённом документе есть узлы приложения, передайте те же декларативные
определения `schema`, что использовались редактором:

```ts
const reference = {
  name: 'app:reference', kind: 'inline', tag: 'span',
  attributes: { 'data-id': { type: 'text', required: true, maxLength: 80 } },
} as const;
const published = createContentView(articleHost, {
  schema: [reference],
  value: saved,
});
```

Определения сохраняют проверенные идентификаторы и атрибуты без установки
редакторских плагинов. JSON с незарегистрированным владельцем отклоняется. В HTML
незарегистрированная семантическая обёртка проходит обычное понижение кодека:
поддержанный текст и безопасная структура остаются, неизвестная идентичность
отбрасывается. Если идентичность важна, зарегистрируйте схему. ID не подтверждает
права на серверную сущность.

## Lifecycle и оформление

`setHTML(html)` нормализует HTML, `setJSON(document)` проверяет JSON схемы v1.
Вход целиком проверяется до замены статьи. Getters/setters вызывают исключение после
уничтожения либо при отключении, переносе к другому родителю или adoption
принадлежащей статьи/контейнера. `destroy()` идемпотентен и сохраняет чужие соседние узлы.

Стили ограничены `.mw-content-view` и используют `--mw-font`, `--mw-font-size`,
`--mw-line-height`, `--mw-text`, `--mw-muted`, `--mw-accent`, `--mw-border`,
`--mw-hover`, `--mw-radius`. CSS редактора и сайта не требуется.
Импорт безопасен без DOM, создание требует браузер. Это не серверный HTML-sanitizer,
не поверхность редактирования и не точный рендерер страниц Office.

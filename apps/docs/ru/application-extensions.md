# Сущности приложения, информационные блоки и переменные

Используйте существующий SDK для прикладного содержимого и передавайте одну схему
редактору и просмотру публикации. Три примера написаны на TypeScript и принадлежат
приложению: это не новые пакеты редактора и не новый формат документа.

## Три примера

| Тип | Сохраняемый источник | Прикладной смысл |
| --- | --- | --- |
| Сущность | Атомарный `span`, `data-id`, буквальная подпись | Ссылка на запись, которую разрешает и авторизует backend |
| Информационный блок | Текстовый `blockquote`, `data-tone="info"` или `"warning"` | Оформленное сообщение или предупреждение |
| Переменная | Атомарный `span`, объявленный `data-key`, буквальный токен | Значение, которое явно подставляется в копию публикации |

ID сущности — непрозрачная строка до 64 UTF-16 единиц. Она не становится URL и
не разрешает доступ. Изменение видимой подписи не подтверждает смену серверной
записи. Атомарные подписи — ограниченный однострочный текст. Информационный блок
принимает до 2000 единиц буквального текста; произвольные вложенные виджеты,
HTML-теги и editable contentDOM в этот рецепт не входят.

Выберите тип и нажмите **Выбрать первый узел**, чтобы связать черновик с реальным
узлом. Измените текст/атрибут и нажмите **Обновить выбранный** или **Удалить выбранный**.
**Отменить** возвращает изменение команды. **Вставить в конец** намеренно выбирает
конец документа, а не прежнюю каретку. SDK по-прежнему проверяет границы вставки.

Любая правка содержимого, начало composition или включение read-only отменяют
актуальность черновика. Перед применением выберите узел заново. Возврат документа
к идентичному HTML не делает прежний черновик актуальным. Сохранённое выделение
не позволяет обходить проверку команды. Read-only и IME блокируют изменения;
загрузка нового документа отменяет старые цели.

## Общая схема и команды SDK

Скопируйте рядом прикладные файлы `types.ts` и `index.ts`. Создавайте новый набор
для смонтированного редактора. Сам импорт файлов не создаёт DOM или глобальный реестр.

<<< @/.vitepress/theme/application-extensions/types.ts

<<< @/.vitepress/theme/application-extensions/index.ts

Передайте `bundle.plugins` редактору или адаптеру. Для просмотра используйте
`createContentView(readerHost, { value: savedJSON, schema: bundle.schema })`.
Просмотр не устанавливает плагины редактирования, не создаёт редактор и не
активирует ссылки на сущности. CSS content-view импортируется отдельно.

`bundle.commands(editor, kind)` предоставляет команды вставки SDK. Прикладные
capture/update/remove дополнительно проверяют ревизию черновика и реальный узел;
SDK повторно проверяет владельца и документ после фокуса перед изменением.
Не сохраняйте захваченные цели после замены документа или unmount. Прикладной
плагин освобождает слушателей ревизии при уничтожении редактора.

## Сохранение, загрузка и отображение

**Сохранить JSON** копирует проверенный документ в локальную память. **Загрузить JSON**
передаёт снимок через ту же схему и явно заменяет текущий документ. Внешняя замена
очищает историю Undo по обычному контракту редактора. Этот пример не создаёт
долговременное хранилище или backend.

Объявленные ID, тона и ключи переменных сохраняются в HTML/JSON. Runtime-аннотация
атома `contenteditable=false` не сохраняется. Отдельный просмотр с общей схемой
оставляет семантические данные. JSON-читатель без определений отклоняет неизвестные
owning-узлы; HTML-читатель выполняет безопасный downgrade кодека, без обещания
сохранить метаданные. Если семантика важна, передавайте соответствующую схему.
См. [отображение сохранённого контента](/ru/content-view).

## Буквальная подстановка переменных

**Показать с переменными** подставляет значения только в отдельную проверенную копию;
редактор и его история не меняются. Объявлены ключи `customer` и `order`. Например,
`customer = <b>Ada</b>` покажет буквальный `<b>Ada</b>`, не создавая B-элемент.
Нет вычисления выражений, произвольной HTML-интерполяции или подстановки URL.
Сущности и информационные блоки остаются в копии публикации.

Неизвестные переданные ключи отклоняются. Отсутствующие собственные значения сохраняют
исходный токен и попадают в `unresolved`; свойства прототипа не становятся значениями.
Каждая строка ограничена 2000 UTF-16 единицами без NUL/управляющих байтов. Один вызов
обрабатывает максимум 100 переменных и 20000 единиц текста замены; превышение границ
отклоняется до возврата результата. Итоговый документ проходит ту же схему.

Это границы небольшого прикладного рецепта. Приложение выбирает разрешённые ключи,
авторизованные источники данных и момент подстановки. Чувствительные значения и
права доступа проверяйте на сервере: метаданные редактора и фронтенд-фильтрация
не являются авторизацией. См. [безопасность](/ru/security).

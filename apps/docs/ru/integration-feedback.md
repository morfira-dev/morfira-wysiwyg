# Сценарии интеграции и обратная связь

Попробуйте законченный сценарий редактирования перед подключением к своему
приложению. Выберите статью для CMS, базу знаний с таблицами или поле формы. Для
каждого варианта есть действия и наблюдаемые результаты с существующими готовыми
инструментами. Это локальные примеры, а не действующие клиентские внедрения или
собранные отзывы.

## Подключите границу своего приложения

Локальное поле содержит готовую панель, подпись, валидацию, read-only, сохранение
с повтором и имитацию загрузки изображения. Смена задачи меняет инструкции, не
заменяя открытый черновик. Закрытие поля уничтожает редактор и локальный сервис;
повторное открытие начинает новый пример. Постоянное хранилище и сервер загрузки
здесь не создаются.

В своём приложении:

- Подключите controlled value и ready-lifecycle адаптера по
  [примеру поля редактора](/ru/editor-field).
- Передайте save/upload callbacks аутентифицированный backend с валидацией,
  авторизацией и обработкой конфликта версий. AbortSignal не отменяет запись,
  которую сервер уже принял.
- Попробуйте типичные [табличные команды и буфер](/ru/plugins) на синтетических
  значениях перед использованием своих материалов.
- Показывайте принятый сохранённый снимок отдельным
  [просмотрщиком контента](/ru/content-view), без второго редактируемого экземпляра.

## Опишите воспроизводимую проблему

Используйте короткий выдуманный документ и укажите точное действие, ожидаемый и
фактический результат. Добавьте выбранные модули и установленную версию. В примере
показана версия из package manifest его сборки: она не подтверждает, какой npm-пакет
установлен в другом приложении. Необязательная версия приложения — короткое
обозначение, например `1.0.0`.

Конструктор не читает текст редактора, HTML/JSON, файлы, ID сущностей, адреса
backend, токены, console logs, storage или содержимое буфера обмена. Информация о
браузере по умолчанию отсутствует. Только после включения опции и нажатия
**«Подготовить отчёт»** добавляется общее семейство браузера, без исходного
user-agent, расширений или списка характеристик устройства.

Шаги ограничены 4000 UTF-16 units, ожидаемое и фактическое поведение — 2000 каждый.
Распространённые адреса, email и похожие на credentials значения отклоняются, чтобы
вы могли заменить их условными обозначениями. Это консервативная подсказка, а не
поиск всех секретов или гарантия обезличивания. Не вставляйте рабочий контент,
настоящие идентификаторы или секреты. Самостоятельно прочитайте каждую строку.

**«Подготовить отчёт»** создаёт буквальный предпросмотр и ничего не отправляет.
Изменение исходного поля отменяет прежний предпросмотр и подтверждение проверки.
Копирование доступно только после явного просмотра. Если нативный clipboard API
недоступен, выделяемый текст остаётся для ручного копирования. Issue или сообщение
автоматически не создаются.

После проверки вы можете вручную открыть
[issue репозитория](https://github.com/morfira-dev/morfira-wysiwyg/issues/new/choose)
и вставить отчёт. Проблемы безопасности воспроизводите на синтетических данных;
не публикуйте настоящие credentials и частные документы в issue.

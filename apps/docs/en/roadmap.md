# Roadmap and limitations

Morfira is an independently implemented lightweight modular TypeScript editor under MIT. The target is ready everyday authoring close to mature editors in common tasks, with a small selected bundle, understandable extensions, modern UI and detailed documentation. Improvements require concrete scenarios and measurements. Full enterprise or office-suite parity is not a commitment.

Supported list and quote operations and their boundaries are described in the [API](/en/api#list-item-selections-and-boundaries). Current execution results are recorded under [Verification and limits](#verification-and-limits).

## Implemented baseline

A single ordinary `blockquote` can be inserted as a separate block in an item at a caret or over a supported selection, preserving its wrapper, source text edges, neighboring bodies and branches. The quote accepts inline content or ordinary paragraphs/headings. Repeated block insertion beside an existing quote retains it as a whole actual node. Inside one supported quote, multiple ordinary paragraphs/headings and a single heading can be inserted at a caret or across its ordinary child bodies. A separate block replacement across one or several ordinary quotes within one item preserves all incoming wrappers at item level and the unselected quoted edge inside the original quote; fully covered quotes and intervening bodies are removed. Entering places the caret in a new empty paragraph before the quoted remainder, leaving at the separate outside suffix start. Endpoints in different quotes are supported within the same item. Every affected quote is fully validated. A separate path also supports consecutive items of one list: retain the first item and move the actual last-item suffix, following bodies and its unselected trailing branches into it. For trailing-only source items, branches from first, intermediate and last items remain after all resulting bodies in source-item order, without coalescing or flattening; the former global body/branch traversal order is not claimed. Different lists/levels, nested quote insertion inside the source quote, semantic/unsupported shapes and native boundary editing remain outside the new path. This is bounded quote editing rather than complete quote support.

A separate structural quote-crossing profile now accepts wrapped own blocks after nested lists. Prefix branches stay before the selection; incoming wrappers precede protected interval branches, then the actual suffix. Following bodies and lists retain their original sequence. A quoted suffix gets its caret paragraph after protected branches. The trailing-only profile remains unchanged. Ordinary same-body outside-quote, native/inline and no-affected-quote interleaved editing remain outside support. Inner block insertion within one ordinary quote now also accepts the interleaved outer item at a caret or over supported selections, preserving all outer body/list nodes in place.

A single ordinary heading can be inserted at a caret or over a supported list selection as a separate body with its own attributes: the source prefix and suffix remain on either side, with the caret before the right suffix. Neighboring bodies, branches and history remain.

The local list-paste extension accepts two or more ordinary paragraphs/headings over a noncollapsed selection, including text within one body, and at a collapsed caret. The source body splits into a prefix and suffix joined to the first and final incoming bodies respectively. Incoming bodies remain inside the retained item, preserving surrounding bodies, branches and history. Arbitrary structural or semantic insertion is not claimed.

The current local slice includes [minimal/standard/extended presets](/en/presets) and the [modern shell, standard panels and extended suggestion UI](/en/editor-ui).

- A versioned document tree, validated HTML/JSON boundaries, selection/formatting, bounded undo/redo history and atomic composable transactions.
- [Selection replacement and text/HTML insertion between ordinary sibling blocks](/en/api#pasting-over-a-selection-between-blocks) within one root, blockquote or cell.
- Nested lists, headings, blockquotes, basic code blocks, colors, alignment and link editing.
- A logical table grid, merged cells, structural operations, column sizing and HTML/TSV range clipboard.
- [Images](/en/images): URLs, alt text, dimensions, captions and application-owned upload callbacks with cancellation.
- [Find/replace](/en/search), [Unicode statistics](/en/statistics), [Markdown shortcuts](/en/markdown), editable-text [mentions/slash suggestions and structural slash actions](/en/suggestions).
- [Instance events](/en/events), selective imports/tree-shaking, CSS variables and [reusable optional link/image/search forms](/en/ui). The homepage and playground use these public forms.
- [RU/EN localization](/en/localization), custom translations and language changes without document replacement. Vue, React, Svelte, Angular 21/22 [adapters](/en/adapters) and an explicitly registered Web Component.
- Local bilingual documentation, installed-tarball consumer checks and [observational benchmarks](/en/performance).

Composition/history and ordinary paragraph/heading keyboard boundaries have bounded contracts and tests. These do not replace real OS IME, mobile keyboard, touch or screen-reader checks. Those areas are not certified or considered fully verified.

## Next milestones

Milestones define development order, not release dates. Each includes a specification, browser scenarios, size measurements and matching RU/EN examples.

1. **Plugin SDK and extensible schema — phase 1 implemented.** Typed commands, payload validation, command state and declarative plugin schema contributions compiled before initial import. Phase 1 preserves format v1: allowed HTML wrappers carry validated semantic markers and metadata. Arbitrary HTML tags, custom node views, atoms, decorations and a new immutable editing model are not promised by this phase.
2. **Input and history correctness — ordinary-block replacement and insertion implemented locally.** Same-parent selection replacement, text and HTML insertion over that selection, safe semantic-heading exits and join barriers are documented in the [API](/en/api#pasting-over-a-selection-between-blocks). Broader structural selections and text drag/drop remain follow-ups. Real IME, autocorrect, dictation and mobile devices need separate checks. Choose history/locality optimizations from measurements on identical documents.
3. **Ready UI and presets — P1–P3 and U1/U2 implemented locally.** Pure minimal/standard/extended compositions, grouped toolbar controls, native block/list/alignment and color controls, reusable link/image/search panels and extended suggestion views are implemented locally. Controls wrap within the host at narrow widths. U3a explicit `overflow: 'more'` with group priorities is implemented and verified; `wrap` remains the default. U3 contextual controls remain future work.
4. **Everyday capabilities — first bounded checklist slice implemented.** Explicit optional commands and external controls are available; native checkbox/gutter interaction and bulk task editing remain future extensions. The bounded horizontal-rule command/UI is now implemented as described above. The first [font-family/size slice](/en/fonts) is implemented and verified: explicit opt-in without preset changes, configured 8–96 px sizes, bounded family syntax, preserved imported units and no font loader. Next: list properties and text direction, alongside future contextual UI following verified U3a overflow. Broader autolink HTML/multiline/email triggers require a separate bounded specification rather than an open-ended must-have promise. Small fullscreen/preview/special-character modules and save-state integration follow their own contracts. Font files never load automatically.
5. **Images and tables.** Clipboard/drop files, pointer/keyboard image sizing, proportions/alignment and upload progress/error/retry. Tables gain an insertion picker, properties, header rows, caption UI, row minimum heights and accessible sizing. Preserve merged-grid correctness and one-step history; applications still own upload transport.
6. **External paste compatibility.** Real Word, Excel, Google Docs, LibreOffice and browser fixtures with a support matrix. Separate safe import, plain text and optional Office normalization. HTML sanitization alone does not prove preservation of Office formatting.
7. **Markdown, persistent mentions and search.** A separate import/export/paste codec with explicit syntax and loss/fallback rules. Durable mention IDs and atomic selection follow the required SDK foundation. Highlighting all search matches must not alter persisted content. Slash actions use the shared command registry.
8. **Optional advanced modules.** Provider-registry video embeds with click-to-load, formulas with a documented format and separately selected resources, content styles and print layouts. DOCX/PDF conversion, review and collaboration require separately requested integration scope and architecture/size assessment.
9. **Continuous security acceptance and quality checks.** Preserve document-validation/resource budgets and threat-specific regression tests. Follow the [security guide](/en/security) for trusted-code, server, upload and CSP boundaries; passing tests do not constitute complete security certification. Every milestone updates RU/EN API, working examples, limits, migrations and size reports. Expand plugin-author guidance, five-wrapper recipes, SSR, controlled values, CSP and uploads. Visual, keyboard, contrast, zoom, reduced-motion, real screen-reader/device and performance checks are acceptance criteria rather than work postponed until all features ship.

Sizes use decimal bytes. JS/CSS are measured after minification; gzip and Brotli are separate. Count each shared chunk once per selected composition. Exclude framework runtimes, source maps and declarations; report fonts and additional locales separately.

| --- | --- | --- |
| Core | Up to 80000 minified JS bytes | Working development target |
| Core | 200000 gzip JS bytes | Hard guard under clarified policy |
| Table / optional entry | 150000 gzip JS bytes | Hard guard under clarified policy |
| Each adapter | 10000 minified JS bytes | Existing guard, framework runtime excluded |
| Standard with selected plugins/UI | 65000 gzip JS bytes | Active measured-profile guard |
| Extended | 110000 gzip JS bytes | Active measured-profile guard |
| Standard/extended CSS | 20000 minified CSS bytes | Active guard for explicit selected CSS |

The user clarified that the original size limits mean gzip, so core/optional entry guards use compressed weight. Stricter existing profile gzip guards remain; duplicate 200000/350000 raw JS profile guards are removed. Raw/gzip/Brotli are still reported separately. Adapters retain their 10000-byte raw guard; small HR/checklist entries keep their own raw guards. Core’s 80000-byte raw goal remains a soft optimization target, not a blocking limit. The final U3a build passed under the revised policy.

Measured headless and ready standard/extended closures now have explicit guards in the size tooling. Each selected graph counts shared code once; preset factories do not load CSS implicitly. A smaller bundle does not establish faster input or lower history memory; measure these independently.

## Format and remaining limits

Persistence uses `EditorDocument` version 1. The previous prototype format has no automatic converter. HTML imports through the supported schema; unsupported markup is normalized. Public API/document changes require explicit compatibility notes and a migration decision.

Reusable forms and [SDK phase 1](/en/plugin-sdk) are implemented. [Autolink](/en/autolink) supports native Space; the local extension adds controlled Enter and one plain-text clipboard URL at a collapsed caret. Shift+Enter, HTML, selected replacement and API insertion are excluded. This bounded extension passed the historical final verification recorded above; input and automatic conversion remain two separate Undo operations. HTML/multiline/email completion requires a separately scoped specification; automatic linking for all input is not promised. Ready presets and U1/U2 UI are implemented locally; U3a overflow is implemented and verified with wrap remaining the default; contextual UI and subsequent SDK phases remain planned. Markdown shortcuts are not Markdown import/export. Current mentions insert editable text without durable IDs. Regex search and simultaneous highlighting of all matches are not implemented; statistics require `Intl.Segmenter`.

Collaboration, track changes, comments, pagination and DOCX/PDF import/export are not implemented. The demo never uploads files; applications own upload transport through a callback. Passing scenarios do not certify security, accessibility, leak freedom or compatibility with arbitrary Office documents.

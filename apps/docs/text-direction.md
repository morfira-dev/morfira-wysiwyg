# Направление текста LTR / RTL

На [главной](/#editor) и в [playground](/playground) открой **«Направление текста»** и загрузи многоязычный пример. Он заменяет документ, сбрасывает историю и задаёт обратное выделение через два соседних абзаца с арабским, ивритом и латиницей. Обычные внешние кнопки сохраняют выделение; Undo/Redo восстанавливают изменения.

## Явное подключение

```ts
import { createEditor } from '@morfira-dev/wysiwyg';
import { textDirection, textDirectionCommands } from '@morfira-dev/wysiwyg/plugins/text-direction';
import '@morfira-dev/wysiwyg/style.css';

const editor = createEditor(host, {
  plugins: [textDirection()],
  value: '<p>مرحبا · שלום · Latin</p>',
});
editor.setSelection(1);
const direction = textDirectionCommands(editor);
direction.setDirection('rtl');
// Позже: direction.setDirection(false) удалит явный атрибут.
```

Плагин подключается отдельно и не входит в пресеты по умолчанию или набор встроенных элементов готовой панели. С пресетом используй `plugins: [textDirection()]`. Полная демка подключает его явно. Нет сторонних зависимостей, обязательного CSS, обработчиков событий, собственного движка двунаправленного текста или загрузки данных. Импорт безопасен при SSR, создание редактора требует браузера. Типы `TextDirection`, `TextDirectionCommands`, `TextDirectionState` экспортируются явно.

## Команда и состояние

`setDirection('ltr' | 'rtl' | false): void` задаёт атрибут каждому целевому блоку. **`false` означает удалить явный dir и наследовать окружение, а не включить LTR.** Направление не меняет text-align, текст, строчное оформление, ссылки или порядок Unicode-символов.

`getState()` возвращает новый `{ disabled, direction, mixed }`. `direction` — сохранённый `'ltr'`, `'rtl'` или `false`, не вычисленный CSS и не распознанный язык. Разные явные значения, включая отсутствие против `'ltr'`, дают `mixed: true` и `direction: false`; для неподдержанного блока возвращаются `disabled: true`, `direction: false` и `mixed: false`. Чтение не меняет документ, выделение и историю.

Неверный аргумент отклоняется до проверки целевого блока, в том числе при неподдержанном выделении или в режиме только чтения. Допустимое значение для неподдержанной цели либо уже установленное значение ничего не меняет: возможность Redo и стили следующего ввода сохраняются. Режим только чтения и составной ввод IME блокируют изменения; внешняя синхронизация документа остаётся разрешённой. Несколько блоков меняются одной транзакцией и одним Undo; команды можно объединить через `editor.transact`. Отсутствующий плагин и сохранённый API после уничтожения вызывают ошибку.

## Какие блоки меняются

Для каждого конца браузерного `Range` выбирается ближайший обычный `p`, `h1`–`h6`, `pre`, `blockquote`, `li`, `td` или `th`. Поддержаны курсор, пустой блок, обратное выделение и последовательность соседних таких блоков с общим родителем. Оба конечных блока включаются, даже при нулевом смещении; между соседями допустимы только пробелы, табуляция и переводы строк ASCII, используемые для оформления HTML. Корневые/внешние позиции, разные родители/уровни, семантические узлы с собственным владельцем и неподдержанные промежуточные узлы блокируют всю операцию.

Оба конца и все цели должны быть в одной ближайшей ячейке либо вне ячеек; пересечение ячеек, в том числе при объединённых ячейках, не поддержано. Поиск целевого блока не проходит сквозь `ul`/`ol`/`table`/`tr`/`figure` или обёртку подписи к внешнему LI или TD. Абзац внутри пункта нацеливает этот абзац, текст непосредственно в пункте без абзаца-обёртки — сам LI. **Диапазон через внутренние абзацы разных LI не поддержан** из-за разных родителей; соседние обычные LI поддержаны.

Меняется сам контейнер, его дочерние узлы сохраняются. Наследование может повлиять на потомков без собственного явного `dir`, но команда не обходит ветки рекурсивно. Внешний интерфейс обязан восстановить актуальное выделение перед действием; демка использует общий `run` стенда. После Undo/Redo применяются существующие ограниченные правила ввода, а не произвольное структурное редактирование.

## Импорт, безопасность и ограничения

Набор тегов относится к канонической схеме после существующих HTML-алиасов: `div dir="rtl"` может стать `p dir="rtl"`; JSON по-прежнему требует канонический тег. При вставке `dir` входящей обёртки сохраняется, если профиль вставки сохраняет саму обёртку. Вставка содержимого одиночного абзаца или присоединение первого блока к целевому оставляет направление целевого блока и может убрать `dir` снятой обёртки. Строчные обёртки для управления двунаправленным текстом автоматически не создаются.

Схема v1 сохраняет `dir="ltr"`/`"rtl"` на `p`, `h1`–`h6`, `pre`, `blockquote`, `ul`, `ol`, `li`, `td`, `th` без установленного плагина. HTML нормализует регистр/внешние пробелы и удаляет неверные значения или атрибут на других тегах. JSON принимает только канонические строки в нижнем регистре на этих тегах; неверный тег, тип или значение отклоняется до изменения документа/истории/уведомлений. Старый читатель может удалить dir и изменить отображение; совместимость без потери данных не обещается. **Изменение JSON-границы:** собственный ключ `dir` с неверным тегом/типом/значением раньше мог отфильтровываться как неизвестный атрибут; теперь он распознаётся и атомарно отклоняется. Для JSON используй только канонические `ltr`/`rtl`; нормализация HTML остаётся отдельным импортным контрактом.

Разделение блока через Enter с копированием обёртки сохраняет `dir`. Enter в конце обычного заголовка также переносит его проверенный явный `dir` в новый абзац. Существующие операции смены тега целого блока, преобразования абзац↔пункт списка, UL↔OL и Markdown копируют только проверенный `dir`, когда оба тега его поддерживают, без произвольных атрибутов и метаданных. Списки с разным явным `dir` не сливаются с потерей границы направления.

При снятии списка через форматирование или поддержанный Backspace в начале первого блока корневого пункта собственные абзацы и заголовки сохраняются. Направление удаляемого LI переносится только на его непосредственные сохранённые P/H-блоки, у которых нет собственного `dir`: явное направление блока не перезаписывается, вложенные ветки рекурсивно не меняются. Отдельный существующий выход по Enter из пункта с единственным пустым блоком превращает его в обычный абзац. Если у пустого блока есть явный `dir`, именно он имеет приоритет перед направлением LI; форма результата остаётся прежней.

Эти ограниченные переходы не обещают сохранения наследуемого направления при любых объединениях, структурных удалениях или снятии вложенных обёрток. Для остальных операций действуют их собственные правила документа.

Не добавлены `dir=auto`, строчные обёртки, `bdi`/`bdo`, CSS `direction`/`unicode-bidi`/`writing-mode`, автоопределение языка или преобразование управляющих символов Unicode. **Отображение двунаправленного текста Unicode остаётся задачей браузера**; эта функция не гарантирует защиту от подмены смысла через визуальный порядок символов, не переставляет текст и не переписывает управляющие символы двунаправленного текста. Нативное отображение направления, маркеров и визуальное перемещение стрелками определяет браузер. Серверная проверка и контекст безопасного отображения остаются обязанностью приложения. Текущие выполненные проверки фиксируются отдельно в [дорожной карте](/roadmap#проверки-и-ограничения).

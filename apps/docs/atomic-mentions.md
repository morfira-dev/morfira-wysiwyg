# Атомарные упоминания с ID

`mentions({ persistent: true, atomic: true })` включает навигацию и удаление упоминания целиком. Оба флага задаются явно: по умолчанию плагин вставляет обычный текст, а один `persistent: true` сохраняет редактируемую ссылку с ID. Этот этап реализован локально; браузерные регрессии написаны, но не запускались. Старые проверки редактируемых ссылок не подтверждают атомарное поведение.

## Подключение

```ts
import { createEditor } from '@morfira-dev/wysiwyg';
import { mentions, getMentions } from '@morfira-dev/wysiwyg/plugins/mentions';
import '@morfira-dev/wysiwyg/style.css';
import '@morfira-dev/wysiwyg/plugins/suggestions.css';

const editor = createEditor(host, {
  plugins: [mentions({
    persistent: true,
    atomic: true,
    provide: ({ query }) => [
      { id: 'user:42', label: 'Анна' },
    ].filter((person) => person.label.toLocaleLowerCase('ru').includes(query.toLocaleLowerCase('ru'))),
  })],
});

const references = getMentions(editor); // { id, text }[]
const dispose = () => editor.destroy();
```

Фабрика проверяет boolean-настройки и отклоняет `atomic: true` без `persistent: true`. Нет отдельного пакета, сетевого провайдера, неявного CSS или новой зависимости. Меню подключается по [существующему контракту](/suggestions). Оформление использует те же `--mw-mention-color`, `--mw-mention-background`, `--mw-mention-radius` и `--mw-mention-padding`, что и [сохраняемые ссылки](/persistent-mentions).

## Курсор, выделение и удаление

| Действие | Поведение в поддержанном обычном текстовом потоке |
| --- | --- |
| ArrowLeft / ArrowRight у границы | Курсор проходит упоминание целиком с учётом LTR/RTL направления блока |
| Shift со стрелкой | Выделение расширяется через весь токен |
| Клик по токену | Можно выделить упоминание целиком |
| Курсор внутри подписи, в том числе через API | Нормализуется к ближайшей внешней границе |
| Частичное прямое/обратное выделение подписи | Расширяется до полной границы упоминания с сохранением направления |
| Backspace сразу после / Delete прямо перед токеном | Удаляет весь span с ID одной операцией Undo |

Пробел после вставленного токена находится **вне** упоминания и остаётся обычным текстом. Если курсор стоит после этого пробела, первый Backspace удаляет пробел; удаление токена — следующее действие. Удаление последнего содержимого оставляет редактируемое место для курсора. Undo/Redo восстанавливает ID, подпись, выделение и атомарное отображение без повторного запроса провайдера.

Поддержаны обычные абзацы/заголовки, тела списков, цитаты и абзацы внутри ячеек, включая объединённые ячейки без изменения сетки. Операции, затрагивающие неподдержанную структуру или другого семантического владельца, отказывают без частичного удаления ID. Это не универсальная модель редактирования через любые контейнеры. Home/End, вертикальная и модифицированная навигация остаются нативными с нормализацией границ; точная визуальная навигация смешанного bidi-текста не заявляется.

Read-only блокирует пользовательские изменения, но допускает внешнюю синхронизацию значения. Composition и `isComposing` не разрешают обработчику удалять токены во время подтверждения IME. Полная совместимость мобильного ввода и screen reader этим этапом не сертифицируется.

## Формат, валидация и миграция

Сохраняемый формат не меняется:

```html
<span data-mw-node="morfira:mention" data-mention-id="user:42">@Анна</span>
```

В живом редакторе доверенная конфигурация выводит `contenteditable="false"` для зарегистрированных упоминаний. Эта аннотация не попадает в `editor.getHTML()` / `getJSON()` и не разрешает произвольный `contenteditable` из входных данных. После внешней загрузки и Undo/Redo отображение выводится заново. При уничтожении освобождаются собственные обработчики, observer и аннотации; другой редактор не затрагивается.

Каждый читатель, которому нужно атомарное поведение, должен включить `atomic: true`. Читатель с обычной зарегистрированной схемой сохранит ID, но оставит подпись редактируемой. Без схемы HTML сохраняет текст и удаляет identity metadata, а JSON отклоняет незарегистрированный маркер. Markdown-кодек продолжает отклонять ссылки с ID, чтобы не потерять их молча.

В атомарном режиме подпись содержит только текстовые дочерние узлы: **1–201 UTF-16 единиц**, без C0/DEL и Unicode-разделителей строк/абзацев. ID сохраняет ограничения 1–256 единиц. Богатые дочерние элементы, пустая или слишком длинная подпись отклоняются при HTML/JSON-валидации до изменения документа. Это намеренное отличие от сохраняемого редактируемого режима.

```ts
import { createDocumentSchema } from '@morfira-dev/wysiwyg';
import { createMentionSchema } from '@morfira-dev/wysiwyg/plugins/mentions';

const schema = createDocumentSchema([createMentionSchema({ atomic: true })]);
const checked = schema.validateDocument(storedDocument);
```

`createMentionSchema({ atomic: true })` проверяет содержимое без провайдера; сама декларация не устанавливает обработчики навигации. Перед включением режима для старых данных проверь подписи. Можно остаться в редактируемом режиме либо явно преобразовать подпись в ограниченный буквальный текст в коде приложения. Автоматического удаления оформления/детей, нового варианта DocumentNode или миграции версии схемы нет.

ID остаётся недоверенной ссылкой на сущность. Приложение проверяет существование, tenant, права и разрешение на уведомления на сервере. Неизменяемость подписи во время пользовательского редактирования не доказывает личность и не защищает от доверенного JavaScript приложения, меняющего DOM/значение напрямую. Lookup и уведомления не выполняются.

## Попробовать

На [главной](/#editor) и в [playground](/playground) раскрой «Атомарные упоминания: курсор и удаление». Загрузка примера заменяет документ. Кнопки ставят курсор перед/после `@Anna` или выделяют весь токен без изменения истории. Попробуй ArrowRight, Shift+ArrowRight, Backspace/Delete и Undo. Соседний раздел сохраняемых ссылок показывает ID и HTML/JSON round-trip. Полная демка явно включает оба флага; значения по умолчанию пресетов не изменены.

## Копирование и вставка

[Буфер атомарных упоминаний](/atomic-mention-clipboard) сохраняет ID в HTML для одного обычного потока и диапазона соседних абзацев/заголовков с общим родителем. В plain text остаются подписи с LF между блоками. Дополнительный API `mentionClipboardCommands(editor)` предоставляет copy/cut/paste без доступа к системному буферу. Дополнительно поддержаны соседние пункты одного UL/OL; полностью выбранные допустимые хвостовые ветки переносятся с иерархией и ID, а концы выделения в разных списках, уровнях и ячейках остаются барьерами. Нативные события используют clipboardData; формат документа и значения по умолчанию не меняются.
